# Repository structure and pipelines

MDM1.org is a static site (plain HTML/CSS/JS) published with GitHub Pages. There is no build step for the source pages; a few scripts generate pages, and one workflow publishes everything.

## Folders

| Path | What lives there |
|---|---|
| `/` (root) | Home page (`index.html`), main pages (`hub.html`, `games.html`, `fight.html`, `chat.html`, `whitepaper.html`, ...), SEO/verification files (`CNAME`, `robots.txt`, `ads.txt`, `llms.txt`, sitemaps, IndexNow keys). These must stay at the root. |
| `pages/` | Auto-generated project/plan pages (`build-pages.js`, registry in `pages-registry.json`, `pages-data.json`). |
| `apps/`, `tools/`, `catalog/`, `categories/`, `discover/`, `learn/`, `projects/`, `assistant/` | Section pages: apps, tools, catalog, discovery portal, learning, local AI assistant. |
| `<lang>/` (`en/`, `fr/`, `zh-tw/`, ...) | Translated copies of the site, 50 languages. Generated by `scripts/build-i18n.js` and `scripts/intl_tools.py` -- do not hand-edit. |
| `css/`, `js/`, `images/`, `audio/` | Shared assets. Narration and music live only in `audio/`; do not add copies at the root. |
| `data/`, `i18n/` | JSON data and translation dictionaries. |
| `supabase/` | SQL schema and migrations (not published). |
| `scripts/` | Build, SEO and automation scripts (not published). `scripts/3d/` holds the source of the 3D layer. |
| `archive/` | Old/broken pages kept for reference (not published). |
| `docs/` | Documentation (not published). |

## Publishing

**One workflow publishes the site: `.github/workflows/deploy.yml`.** It checks page quality, generates game landing pages, injects the menu, share card and 3D layer (`scripts/inject_menu_and_card.py`), copies a clean artifact to `_site/` and deploys it. Everything not needed by visitors is excluded there (`scripts/`, `supabase/`, `archive/`, `docs/`, markdown files, root `*.opus`).

Other workflows that change content (`generate-pages`, `trend-pages`, `publish-i18n`, `publish-intl-tools`, `add-app`) commit to `main` and then start `deploy.yml` with `gh workflow run deploy.yml`. Pushes made with the default `GITHUB_TOKEN` do not trigger it on their own, and a second deploy path would publish a different, unchecked copy of the site and collide with it. Keep it that way: **do not add `deploy-pages` to any other workflow.**

Keep the published artifact lean (it is reported in the deploy log). Very large artifacts make the Pages "syncing_files" step time out.

## Workflows

| Workflow | Purpose | Schedule (UTC) |
|---|---|---|
| `deploy.yml` | Publish the site | on push to `main`, manual |
| `generate-pages.yml` | One new project page per day (quality-gated), then deploy | 06:30 daily, manual |
| `update-games.yml` | Refresh the games catalog | 02:00 daily |
| `rea-scout.yml` | Scout opportunities (additive) | 05:00 daily |
| `trend-pages.yml` | New trend tool page, then deploy | 07:00 daily |
| `content-check.yml` | Daily content and site check | 08:00 daily |
| `publish-intl-tools.yml` | Translate tools/apps into 20 languages | 09:30 daily |
| `publish-i18n.yml`, `seo-build.yml`, `add-app.yml` | Translated pages, SEO build, add an app from Scout | manual / dispatched |
| `Rotate-theme.yml` | Rotate the games page theme | every 14 days |
| `indexnow-games.yml`, `indexnow-sitemaps.yml` | Ping search engines | manual / dispatched |
| `smoke-all.yml`, `models-probe.yml` | Diagnostics | manual |

## Local preview

```bash
python3 -m http.server 4174        # plain source, no 3D layer
```

To preview with the menu and 3D layer, copy the repo to a scratch folder, run `python3 scripts/inject_menu_and_card.py --root <copy> --write`, and serve that copy.
