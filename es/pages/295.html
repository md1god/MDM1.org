Specraft — Plan de proyecto completo

Convierte cualquier aplicación web en un plan de reconstrucción listo para el agente de programación.

Plan de ejecución de un proyecto digital: idea, público, producto, ingresos, lanzamiento y riesgos. Aún sin lanzar.

Plan de producto: Specraft

1) Público objetivo

• Equipos pequeños y startups que quieren crear una integración (integration) con una app existente sin documentación.

• Desarrolladores de backend con sistemas antiguos (legacy) sin API documentada.

• Ethical hackers y equipos de seguridad que necesitan entender rápido los auth flows de los sistemas que evalúan.

• Analistas de producto y Competitive Intelligence que estudian en profundidad la técnica de los productos rivales.

• Freelancers que reconstruyen funciones similares para clientes.

2) Diferenciadores

1. Entradas flexibles: enlace vivo, archivo HAR o grabación de pantalla — no depende de una sola fuente.

2. Salidas ejecutables: OpenAPI spec + mapa arquitectónico + plan de reconstrucción en tareas, listo para un AI coding agent con mínima edición manual.

3. Feedback loop: compara las salidas con el comportamiento real de la app y corrige los inferred fields.

4. Privacidad por diseño: procesamiento local o isolated workspaces, y modo que bloquea el envío de datos sensibles a terceros.

5. Interfaz árabe nativa y detección de patrones en apps no inglesas — mercado descuidado.

6. Plan gratuito: análisis mensuales limitados, sin tarjeta.

3) Alcance de la v1 (máximo 8 tareas)

1. Importar un HAR y extraer solicitudes y respuestas (endpoints, methods, status codes).

2. Analizar un enlace directo con un crawler dirigido que construya un routes map y el patrón session/auth.

3. Inferir JSON schemas de muestras de respuesta, separando lo inferido de lo confirmado.

4. Generar una OpenAPI 3.1 spec válida (valid) con validación automática.

5. Mapa arquitectónico: componentes, dependencias y puntos de almacenamiento detectados.

6. Plan de reconstrucción con tareas numeradas, listo como prompts para un agente de programación.

7. Exportación múltiple: openapi.yaml, Markdown y un paquete JSON único.

8. Un workspace con audit log y política de retención de datos.

4) Precios y modelo de ingresos

· Plan · Precio · Contenido ·

· Gratis · $0 · 5 análisis mensuales, solo exportación OpenAPI, marca de agua opcional ·

· Pro · $19/mes · operaciones casi ilimitadas, mapa arquitectónico + plan, exportación completa, comparación de versiones ·

· Team · $49/usuario/mes · workspaces compartidos, permisos, audit log, prioridad de proceso ·

· Enterprise · precio a medida · self-hosted, retención personalizada, soporte e integraciones SSO ·

Otros ingresos: API access por llamada y plantillas de reconstrucción de pago (SaaS, paneles, tiendas).

5) Lanzamiento global con canales gratuitos

1. Product Hunt / Hacker News / V2EX / Reddit (r/webdev, r/nextjs): lanzamiento con demo en vivo (split-screen: app vs spec generada).

2. Vídeo corto en YouTube Shorts y X/Twitter: una app conocida a OpenAPI en menos de 60 segundos.

3. SEO técnico: comparaciones y extracción de API de 10 apps famosas (legal y éticamente).

4. GitHub: CLI de código abierto que genera la spec localmente — imán para desarrolladores; el hosted es el producto de pago.

5. Comunidades Developer Arab, Telegram y Discord: versión árabe completa como primera característica.

6. Alianzas con comunidades de AI Agents: docs listas para un MCP server que permita invocarla.

7. Si Dios quiere: campañas de micro-influencers en comunidades no-code y SaaS builders.

6) Riesgos (legales y técnicos)

Legales:

• Peligro de infringir derechos de propiedad intelectual al copiar apps protegidas por copyright: condiciones de uso que exijan permiso y restrinjan las salidas a interoperabilidad y fines educativos.

• ToS de las apps objetivo: el crawling puede violarlos — ofrecer HAR o grabación manual como alternativa y límites de velocidad claros.

• PII en llamadas: cifrado, retención limitada y redacción automática antes de almacenar.

• DMCA y retiradas: proceso de respuesta claro y previo.

Técnicos:

• Precisión limitada de los inferred schemas, sobre todo en SPA con llamadas dinámicas: mostrar confidence por campo, no dar suposiciones por hechos.

• Cambios anti-bot y rotación de IP: priorizar HAR reduce la necesidad.

• Coste computacional: ajustar quotas y usar modelos más pequeños en el análisis rutinario.

• Actualización continua de OpenAPI y validación automática en CI.

7) Nombre y eslogan
