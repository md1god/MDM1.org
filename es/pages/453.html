Plan de producto: Revisión de código mediante ejecución real (Runtime AI Review)

El problema: el análisis estático (static analysis) lee el código y no lo ejecuta; descubre errores de sintaxis e ignora errores de comportamiento: ruta de petición rota, botón que no funciona, experiencia de login rota, o condición edge que falla con datos reales. Resultado: viaje "regular" a producción, alta tasa de rebote en cada reporte.

1) Público objetivo

· segmento · tamaño · dolor principal · qué busca ·

· equipos de desarrollo (5–50 devs) en fases de entrega diaria · mayor · revisiones de PR lentas, errores de comportamiento aparecen tras el merge · CI que detiene PR roto automáticamente con prueba entregable ·

· devs de SaaS y e-commerce · grande · caída de retención y soporte por bugs en runtime · escenarios E2E generados automáticamente con cada cambio ·

· equipos de frontend/full-stack · medio · no hay dispositivo macOS/Windows que ejecute entorno de producción localmente · ejecución real dentro de runner aislado y documentado ·

· testers QA manuales · pequeño · repetición de casos manuales · convertir exploración manual en escenarios reejecutables ·

· equipos distribuidos geográficamente (incl. mercados MENA) · medio · tiempos de reacción largos entre regiones · pruebas visuales (vídeo + logs) que sustituyen Reproduce local ·

Interno: principalmente devs de empresas y productos digitales (Dev/Full-stack), y con el tiempo operadores de plataformas QA y equipos de release.

2) Puntos diferenciales (por qué elegir nuestro producto)

1. Ejecución dentro de tu propia infraestructura CI: funciona en runner aislado (self-hosted) o runner cloud que elijas tú — no subimos tu código a nube de terceros. Resultado: mayor privacidad, menor coste, cumplimiento más fácil.

2. Ejecución incremental (Incremental): mapa de dependencias entre rutas, componentes y acciones, así solo se ejecutan los escenarios afectados por el cambio — recorte drástico de coste y tiempo frente a ejecución completa cada vez.

3. Paquete de evidencias verificable: vídeo WebM + logs de consola + pestaña red + capturas DOM + trazas de pila con números de línea, archivos y selectores precisos — informe listo para convertir en ticket de soporte o bug.

4. Reproducción determinista: seed fijo + simulación de tiempo, red y zona horaria + fijación de versiones ⇒ mismo fallo se repite con mismos números, sin flakiness aleatorio.

5. Nativo de CI no plataforma aparte: salidas SARIF y JUnit + comentario automático en PR + posibilidad de bloquear merge via Branch Protection. No pide al equipo cambiar sus costumbres.

6. Flexibilidad de coste: BYO-LLM (tu clave) + modo "sin LLM" para escenarios existentes + techo claro de tokens y duración por ejecución.

7. Núcleo open source con licencia permisiva + versión enterprise auto-hospedada: gratis siempre para proyectos abiertos, y vendible a empresas que prohíben SaaS externo.

8. Diseño totalmente nuevo: arquitectura independiente (CLI + Agent + Adapter layer), identidad visual nueva, y modelo de interacción (Evidence-first) no copiado de ningún otro producto.

3) Alcance de la v1 (máx. 8 tareas)

1. CLI + GitHub Action / GitLab CI: comando único vigilo run --pr 128 ejecuta la revisión dentro de runner aislado, con flag --local para correr en máquina del dev.

2. Entorno de ejecución seguro: contenedor efímero sin secretos, recursos limitados, red aislada por defecto (deny-all con whitelists), y auto-limpieza tras la ejecución.

3. Generación de escenarios desde el PR: análisis del diff + descripción del PR + arquitectura del proyecto (openapi/nombres de pantallas) para generar pasos de navegación ejecutables (driver tipo Playwright escrito desde cero).

4. Agente explorador (Budgeted Explorer): navega interfaces desconocidas con presupuesto de tiempo/tokens definido, y descubre rutas rotas que no cubre ningún escenario.

5. Paquete de evidencias: grabación de vídeo + logs + red + capturas DOM + trazas, subidas como archivo comprimido con versión navegable localmente.

6. Localización precisa del fallo: vincular stack trace a números de línea + reproducción copiable (comandos/pasos/datos) en lugar de "no se pudo ejecutar".
