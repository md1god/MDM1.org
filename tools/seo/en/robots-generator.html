What do these directives mean?

A file typically starts with a User-agent group, followed by instructions such as Allow and Disallow. Rules apply to crawlers that choose to follow the protocol, and syntax details may vary across implementations. A Sitemap line points crawlers to an XML sitemap; it does not guarantee that every URL will be discovered or indexed. Check that the sitemap is valid and publicly reachable.

Check the host and paths

Place the file at the root of the correct host. Rules for https://example.com/robots.txt do not automatically apply to a separate subdomain such as blog.example.com. Review each path carefully, and avoid blocking CSS or JavaScript resources needed to render a page. If you need multiple user-agent groups or special crawler instructions, consult the current documentation for your target search engine before publishing.

Crawling, indexing, and privacy

Allowing a crawl does not guarantee indexing, and disallowing a path does not reliably remove a URL already known to a search engine. If you need to prevent indexing, use a supported indexing control and make sure the crawler can access the signal. Confidential pages require server-side authentication and authorization. Listing a hidden path in robots.txt can reveal its name rather than protect it.

Frequently asked questions

Should I use Disallow: / to keep my website out of search?

Do not use that broad rule on a public site you want crawled; it blocks crawling for compliant bots across the host. Use narrowly scoped rules only after understanding and testing their effect.

Will this protect my admin area?

No. Anyone who can reach a public URL may still visit it. Use authentication, authorization, and appropriate server controls.

Can robots.txt reference multiple sitemaps?

Yes. Multiple complete Sitemap URLs can be listed when needed. Confirm each is valid and reachable and that the sitemap follows the expected XML format.
