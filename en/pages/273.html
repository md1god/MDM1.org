Masar CI — Full Project Plan

From code to deployment in one step.

Full execution plan for a new digital project: idea, audience, product, revenue model, rollout, and risks. Under construction, not yet launched.

1) Target Audience

• Small and medium teams (2–30 developers) wanting a lightweight CI/CD system on their own server, without complexity.

• Companies seeking an affordable alternative to expensive CI/CD platforms, with full control over their data and hardware.

• Open-source developers and self-hosting communities (small VPS, ARM boards, home machines).

• DevOps engineers at startups who want to run pipelines locally before pushing them to the cloud.

2) Why choose us

• Local-first: one command runs the pipeline on the dev's machine with the same result as on the server, reducing "works on my machine" issues.

• One documented config file: every step read from a simple YAML file with instant validation and fix suggestions in the editor.

• Extremely lightweight: two components only (server + runner), SQLite by default, under 100MB idle memory.

• Strong execution isolation: each job in a separate container with resource limits and a restricted network, plus auto cleanup.

• Built-in cache: reuse build results and dependencies between attempts, no external add-ons.

• Full Arabic and English interface from day one, with a visual editor reviewing step results live.

• Extensible via unified plugins (one stable interface for all official and community plugins).

3) First release scope (max 8 tasks)

1. Server (projects, permissions, job logs) in Go with SQLite storage.

2. Runner using Docker/Podman containers with resource limits and an isolated network.

3. YAML file reader for pipelines with instant validation and clear error messages.

4. Integration with GitHub/GitLab/Forgejo: read pushes, create commits, link pull requests and checks.

5. Security: secret encryption, per-project permissions, member job isolation.

6. Web interface (React) showing each step's status, live logs, and artifact downloads.

7. Built-in cache + restart from a specific step.

8. CLI tool to run the pipeline locally and validate the file before pushing.

4) Pricing and Revenue Model

· Free (Self-hosted) · $0 · Unlimited runs on your servers, all core features open ·

· Free Cloud · $0 · 3 projects, 500 execution minutes per month, 1GB storage ·

Revenue: cloud subscriptions, extra execution minutes, enterprise support (SLA), paid pipeline templates.

5) Global Rollout Plan (free channels)

1. GitHub/Social: open repository + landing page + short screen clips on X and LinkedIn.

2. Communities: posts on Reddit (r/devops, r/selfhosted), Hacker News (Show HN), self-hosted forums.

3. Arabic and English content: articles on Dev.to, Hashnode, Midudev, plus tutorial videos on YouTube.

4. Documentation as marketing: "start in 5 minutes" guides and SEO-ready templates.

5. Weekly blog: real CI/CD problem breakdowns and performance comparisons with numbers.

6. Discord/Matrix community + Ambassadors program for universities and developer groups.

7. Plugin and template directory: community publishing plus ongoing search traffic.

8. /Product Hunt and OSS meetups: coordinated launch with temporary cloud plan offers.

6) Risks (legal and technical)

Legal:

• Trademark similarity: check registration before launching in target markets.

• Licensing: pick a clear license (e.g. Apache-2.0) and ensure Go dependencies and API interfaces are compatible with it.

• Never copy docs, design, or plugin names from existing products; write from scratch on open standards (OCI, Git, YAML).

• Data privacy: GDPR when hosting logs and secrets of European customers.

Technical:

• Runner security: external code may expose the server; handled via container isolation, restricted networks, and resource limits.

• Secret leakage: encryption at rest, fine-grained permissions, and audit logs.

• Reliability: no lost jobs on failures, via rolling logs and resumable state.

• Scaling: SQLite to start, but design the storage layer to move to PostgreSQL early.

• Competition: big paid platforms on price and performance; differentiate via lightness, local execution, price.

7) Proposed Name and Tagline

Proposed name: Masar CI

Tagline: From code to deployment in one step.
