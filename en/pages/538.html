KhaytGrid — Complete Project Plan

We weave public energy data into one fabric ready for analysis and verification.

Plan for a new digital project: idea, audience, product, revenue, rollout, risks. Not launched.

1) Target audience

• Energy, climate, economics researchers: linkable, comparable, citable data.

• Investigative journalists: reliable numbers fast, traceable to source.

• Policymakers/regulators: utility, market, and price comparisons over time.

• Nonprofits, think tanks, students: free alternative to costly commercial databases.

• Investment analysts and utility planners: API and clean outputs for their tools.

• Problem: public data is scattered across files, PDFs, and pages with conflicting names, IDs, and formats; cleaning, linking, verification outlast analysis.

2) Differentiators

• Source for every number: provenance log with source file, date, confidence, transformations.

• Unified identifiers: standardized facility, plant, and generator names; review queue for ambiguity.

• Analysis-ready: Parquet/CSV, SQL, API, Python notebooks, no cleaning.

• Hybrid PDF extraction: deterministic rules + language models + human review.

• Reproducible snapshots: each release has a fingerprint and version, so analyses can rerun.

• Free start, no lock-in: open schema/connectors, free core data; pay for scale/convenience, not access.

• Original code and identity: built from scratch, not copied from any existing product.

3) First-version scope (max 8 tasks)

1. Open Canonical Schema for facilities, generators, utilities, fuels, capacity, generation, emissions, and prices.

2. Connectors for EIA-860/923, FERC Form 1, and ISO interconnection queues in three markets; monthly updates.

3. PDF table extraction with validation rules, confidence scores, and human review.

4. Entity Resolution with stable identifiers per facility/plant/generator.

5. Signed snapshots with full provenance per field and transformation.

6. Search UI, REST API, SQL endpoint, Python client, Parquet/CSV export.

7. Data quality dashboard and alerts for source changes, schema drift, and anomalies.

8. Jupyter notebook gallery and templates for journalism, research, and policy.

4) Pricing and revenue

· Plan · Price · Key inclusions ·

· Free · $0 · Core data, monthly updates, 10,000 API calls/mo, 100MB export, community notebooks ·

· Pro · $29/month · Daily updates, 1M API calls, 10GB export, alerts, saved queries, private workspaces ·

· Team · $149/month · 10 seats, SSO, shared projects, audit log, 5M API calls ·

· Enterprise · From $12,000/year · Custom connectors, private/on-prem deployment, SLA, training, priority support ·

Other revenue: custom research, dataset sponsorship, grants, institutional partnerships. Core data stays free; personal data is never sold.

5) Global rollout with free channels

• Phase 1 (0–6 months): US, Canada, via search visibility for utility/facility pages and price reports.

• Phase 2 (6–18 months): UK, EU, Australia, via jurisdiction packs and extensible schemas.

• Phase 3 (18 months+): Latin America, Asia, and Africa, via local partnerships and translated docs.

Free channels:

• Open GitHub repo: schema, connectors, docs, clear license.

• Datasets on Hugging Face, Kaggle, Zenodo with citable DOI.

• Educational content and SEO: guides, analysis examples, utility/price comparisons.

• University, journalism-school, and nonprofit data-center partnerships; free workshops.

• Discord community, monthly Q&A, student/researcher ambassadors.

• PyData, NICAR, Open Data Day, energy hackathons.

• YouTube, newsletter, Arabic/Spanish/French/Portuguese translations.

6) Risks (legal and technical)

Legal:

• Comply with source terms, robots.txt, and rate limits; prefer official APIs and aggregated downloads.

• Review licenses; publish facts with source links, not copied protected documents.

• GDPR/CCPA privacy, data minimization, no personal-data sales.

• Clear disclaimer, error-correction policy, published changelog.

• Check trademark and name before launch.

Technical:

• PDF extraction errors and model hallucinations: validation, confidence scoring, human review, regression tests.

• Source schema changes: monitoring, independent connector versioning.

• Incorrect entity merging: conservative thresholds, review queue, reversibility.

• Data volume/cost: columnar storage, incremental updates, caching.

• API abuse: keys, quotas, rate limits.

• Reproducibility loss: immutable snapshots, verification fingerprints, backups.

7) Proposed name and tagline

Name: KhaytGrid

Tagline: We weave public energy data into one fabric ready for analysis and verification.
