Meshara — Complete Project Plan

Add multiplayer to your game in one hour, with virtual server authority and a ready relay network.

Complete execution plan for a new digital project: the idea, audience, product, revenue model, go-to-market plan, and risks. The project is under construction and has not launched yet.

An original product plan: a ready-made multiplayer networking platform for engines

1) Target audience

• Small indie game studios (1–10 developers) that want multiplayer without building server infrastructure.

• Hackathon and game jam teams that need multiplayer running within hours.

• Unity and Godot developers, web game developers, and university students and clubs.

• Mid-sized studios seeking a self-hostable alternative and wanting to avoid lock-in to a closed service.

2) Differentiators (why choose our product)

• Managed relay + automatic NAT traversal with no server setup or infrastructure purchase.

• Server authority by default with client prediction and reconciliation, reducing cheating and divergence.

• Multi-engine support: Unity, Godot, and web through one SDK, instead of lock-in to a single engine.

• Declarative state synchronization and compressed deltas automatically reduce bandwidth usage.

• In-editor monitoring tools: RTT, packet loss, bandwidth, and a network simulator for testing.

• Open-core model: the core is open and free, and the managed service funds development.

• Generous free tier with no cut of game revenue.

3) Scope of the first version (maximum 8 tasks)

1. A C# SDK core for declarative state synchronization with deltas and basic compression.

2. Server-authority model + client prediction and reconciliation.

3. A managed relay service with automatic NAT traversal and WebRTC/QUIC support.

4. A rooms, lobby, and simple matchmaking interface via REST + SDK.

5. An in-editor network inspector (RTT, lost packets, bandwidth).

6. A network simulator for testing (latency, jitter, packet loss).

7. A starter pack and two sample projects (2 players and 8 players) with documentation.

8. A web dashboard for keys, quotas, rate limits, and anti-cheat basics.

4) Pricing and revenue model

• Free: unlimited development, up to 50 concurrent players, and 20 GB relay per month.

• Indie: $25 per month — up to 500 concurrent players and 500 GB.

• Studio: flexible usage (e.g., $0.02/GB + CCU tiers) with no minimum.

• Enterprise: self-hosting license and priority support.

• Self-hosting the core is free; revenue comes from managed relay, support, and compliance, with no cut of game revenue.

5) Global go-to-market plan with free channels

• Publish the core on GitHub with documentation and runnable examples.

• Discord community and specialized Reddit channels (gamedev, Unity, Godot).

• A devlog video series on YouTube and TikTok/Shorts explaining multiplayer building step by step.

• Offer the package for free on the Unity Asset Store and Godot Asset Library.

• Sponsor game jams and provide ready-made templates for teams.

• Technical articles on Dev.to and Hashnode, and launches on Product Hunt and Hacker News.

• Localize documentation (Arabic, Spanish, Portuguese) and partner with university clubs.

• Open-source sample games that demonstrate performance and serve as references.

6) Risks (legal and technical)

• Legal: compliance with open-source library licenses, player data privacy (GDPR/CCPA), export encryption regulations, and asset ownership in sample projects.

• Technical: NAT traversal reliability, relay scaling cost, cross-platform determinism differences, engine API changes, cheating and DDoS, and browser WebRTC limitations.

7) Proposed name and marketing tagline

Proposed name: Meshara

Marketing tagline: Add multiplayer to your game in one hour, with virtual server authority and a ready relay network.
