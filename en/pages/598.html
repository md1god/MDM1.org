Qirtas — Full Project Plan

We turn the web into clean data ready for AI agents in a single request.

A full plan for a new project: idea, audience, product, revenue, growth, and risks. Under construction, not yet launched.

Product plan: web data extraction for intelligent agents

1) Target audience

• AI developers building agents or RAG systems who need clean web content.

• Small startups that don't want to build scraping and processing from scratch.

• Data analysis and research teams that regularly collect content from multiple sites.

• Automation agencies and no-code makers (n8n, Make) seeking ready integration.

• Researchers and academics archiving pages and references in structured formats.

2) Differentiators

• A real free start: permanent monthly credit, no card, enough for small production.

• Agent-ready outputs: clean Markdown, user-defined JSON schemas, and screenshots when needed.

• Native agent design: async jobs, Webhooks, an MCP server, an official SDK, not scraping interfaces.

• Strong Arabic/multilingual support: RTL, diacritics, mixed-language pages.

• Cost transparency: a clear usage counter per request, and a cache that cuts duplicate calls and bills.

• Built-in compliance: robots.txt and site policies by default, plus an audit log per operation.

• No lock-in: data export, open-standard interface, and later self-hosting of the enterprise version.

3) First version scope (max 8 tasks)

1. extract endpoint: one link to clean Markdown, removing menus, ads, and noise.

2. extract endpoint with custom JSON schema for specific fields (price, title, date…).

3. JavaScript rendering via headless browser with smart wait for load.

4. Scoped crawl endpoint to explore a site to a set depth and return a link map.

5. search endpoint to find pages then extract the best results directly.

6. API keys, quotas, balance, a simple dashboard, and usage log.

7. Async jobs + Webhooks + initial SDK (Python, TypeScript) and an MCP server.

8. Cache, error logging, automatic retry, full docs, and ready examples.

4) Pricing and revenue model

• Free: fixed monthly credit (e.g. 500 operations) and a low rate limit, no card.

• Pay-as-you-go: pay per use after the free tier, per operation or per thousand pages.

• Starter / Growth: larger credit, processing priority, wider limits, lower per-operation price.

• Enterprise: usage agreement, custom limits, SLA, invoicing, and self-hosting.

• Extra revenue: a commission-based marketplace of ready templates, and paid add-on endpoints (screenshots, PDF, complex tables).

• Pricing principle: one clear credit, rollover of unused credit for a limited period, and an annual discount.

5) Global growth plan with free channels

• Open-source SDK and CLI on GitHub with practical examples and a strong README.

• MCP server listed in MCP directories and agent tool marketplaces.

• SEO-optimized docs, comparison guides, and "how to" guides per use case.

• Honest launches on Product Hunt, Hacker News, and Reddit (r/LocalLLaMA, r/MachineLearning).

• Free integrations with LangChain, LlamaIndex, n8n, Make, and Zapier.

• Short educational YouTube videos and written tutorials on dev.to and Medium.

• Discord community and a weekly newsletter with use cases and updates.

• University competitions and hackathons, plus open-source sponsorship (Good First Issues).

6) Risks (legal and technical)

Legal:

• Changing site terms and copyright; solution: respect robots.txt, an acceptable use policy, and domain exclusions.

• Personal data protection (GDPR/CCPA); solution: minimal collection, no long-term storage by default, and deletion tools.

• User responsibility for extracted content; solution: clear terms of service and permitted-use guidance.

• Varying regional legal risks; solution: periodic review and flexible domain blocking.

Technical:

• Anti-scraping, CAPTCHA, and IP blocking; solution: network diversification, retries, and clear limits.

• High JavaScript rendering cost; solution: smart caching, lightweight rendering when possible, and clear limits.

• Fragile extraction when designs change; solution: flexible schemas, monitoring tests, and alerts.

• Prompt injection via web content and data poisoning; solution: sanitize outputs and mark untrusted content.

• Interface security (SSRF, quota abuse); solution: blocked-domain list, rate limits, and anomaly monitoring.

• Reliability and scale; solution: queues, monitoring, and a recovery and gradual-availability plan.

7) Proposed name and tagline

Proposed name: Qirtas (قِرطاس)

Tagline: We turn the web into clean data ready for AI agents in a single request.
