Vigilo — Complete Project Plan

Run your app on every pull request and find the root cause of failures instead of guessing.

Complete implementation plan for a new digital project: idea, audience, product, revenue model, go-to-market plan, and risks. The project is under development and not yet launched.

Product Plan: Runtime AI Review

Problem: Static analysis reads code but doesn't run it; it detects syntax errors while ignoring behavioral errors: a broken request path, a non-functional button, a disabled login flow, or a boundary condition that fails with real data. The result is a "fire drill" to production with a high return on every report.

1) Target Audience

· Segment · Size · Core Pain · What They Look For ·

· Development teams (5–50 developers) in daily delivery cycles · Largest · Slow PR reviews, behavioral bugs appear after merging · CI automatically blocks faulty PRs with deliverable evidence ·

· SaaS and e-commerce developers · Large · High support load due to runtime bugs · E2E scenarios generated automatically with every change ·

· Frontend/Full-stack teams · Medium · No local macOS/Windows machine runs the production-like environment · Real execution inside an isolated, documented runner ·

· Manual QA testers · Small · Repetitive manual test cases · Convert manual exploration into reusable, re-runnable scenarios ·

Internally, the primary users are company developers and digital product teams (Dev/Full-stack), expanding over time to QA platform operators and release teams.

2) Points of Differentiation (Why Choose This Product)

1. Execution within your own CI infrastructure: Runs on an isolated runner (self-hosted) or a cloud runner of your choice — we do not upload your code to a third-party cloud. Result: higher privacy, lower cost, and easier compliance.

2. Incremental execution: Dependency map between paths, components, and actions ensures only scenarios affected by a change run — drastically reducing cost and time compared to full runs.

3. Verifiable evidence bundle: WebM video + Console logs + Network panel + DOM snapshots + stack traces with line numbers, files, and precise selectors — a report ready to convert into a support ticket or bug report.

4. Deterministic reproduction: Fixed seed + simulation of time, network, and timezone + pinned versions ⇒ the same failure reproduces with the same numbers, with no random flakiness.

5. Built for CI, not a separate platform: SARIF and JUnit outputs + automatic PR comments + merge blocking via Branch Protection. No change to team workflows required.

6. Cost flexibility: BYO-LLM (your own key) + "no LLM" mode for existing scenarios + clear caps on tokens and duration per run.

7. Open-core with suitable license + self-hosted enterprise edition: Free forever for open-source projects, and sellable to enterprises that prohibit external SaaS.

8. Ground-up design: Independent architecture (CLI + Agent + Adapter layer), new visual identity, and an evidence-first interaction model not copied from any existing product.

3) Scope of First Release (Max 8 Tasks)

1. CLI + GitHub Action / GitLab CI: A single command `vigilo run --pr 128` runs checks inside an isolated runner, with `--local` for developer machines.

2. Secure execution environment: Temporary container with no secrets, limited resources, network isolated by default (deny-all with whitelists), and automatic cleanup after execution.

3. Scenario generation from PR: Analyze diff + PR description + project structure (openapi/screen labels) to generate executable navigation steps (Playwright-like driver written from scratch).

4. Budgeted Explorer Agent: Browses unknown interfaces with time/token budgets and discovers broken paths not covered by any scenario.

5. Evidence bundle: Records video + logs + network + DOM snapshots + traces, uploaded as a compressed archive with a locally browsable version.

6. Precise failure localization: Links stack traces to line numbers + copyable reproduction (commands/steps/data) instead of "execution failed".

7. CI integration: SARIF + JUnit + PR comments + merge blocking + re-run gating on flakiness.

8. Deterministic reproduction + metrics: Seed/mock for time/network, `reportbaseline` for diff comparison, and a lightweight PR dashboard (cost, duration, number of affected checks).
