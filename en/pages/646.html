Rafid Edge — Complete Project Plan

Connect any industrial device to one network in minutes, with no mandatory cloud and no vendor lock-in.

Complete implementation plan for a new digital project: concept, audience, product, revenue model, go-to-market, and risks. The project is under construction and not yet launched.

1) Target Audience

• OT automation/control engineers in small and medium factories.

• System integrators linking equipment across vendors and protocols.

• Utilities: water, electricity, renewables, and building automation (BACnet/KNX).

• Machine manufacturers (OEMs) needing a unified gateway.

• IoT/data teams building Grafana dashboards or cloud platforms.

• Emerging markets, municipalities, and budget-limited industrial projects.

2) Differentiators

• Genuinely free start: community edition runs locally, no mandatory cloud or credit card.

• Automatic discovery and guided setup: connection drops from days to minutes.

• WebAssembly-isolated plugins: run new protocols safely, with digital signing and instant updates.

• Unified data model: typed tags, quality, timestamps, and ready mapping templates.

• GitOps: traceable, reviewable, reversible profiles instead of hidden settings.

• Store-and-forward: no data loss during outages, plus local rules and alerts.

• Openness: open SDK; MQTT/Sparkplug B, OPC UA, REST, Kafka, InfluxDB/Timescale; no lock-in.

• Lightweight/secure: Raspberry Pi and ARM/x86, read-only default, signed updates.

• New identity: simple industrial UI in Arabic/English; code written entirely from scratch.

3) First Release Scope (Max. 8 Tasks)

1. Rust runtime core with YAML config loader and CLI.

2. WebAssembly plugin SDK with isolation, permissions, and signing.

3. Four protocols: Modbus TCP/RTU, Siemens S7, OPC UA Client, EtherNet/IP.

4. Initial automatic device discovery and tag import.

5. Unified data model with buffer and Store-and-Forward.

6. Northbound: MQTT/Sparkplug B, OPC UA server, REST.

7. Web UI: device wizard, live tag browser, connection health, alerts.

8. Deployment: Docker, ARM/x86, one-command install, docs, device simulators.

4) Pricing and Profit Model

• Community: free forever, self-hosted, one site, up to 25 devices/10,000 tags, community support.

• Growth: $79/site/month, up to 100 devices, config backup, email support.

• Business: $299/site/month, unlimited devices/tags, HA, SSO/RBAC, audit logs, 24/7 support, SLA.

• Enterprise: custom: fleet management, custom protocols, security review, training.

• Cloud: free tier with simulators and two real devices, then usage-based pricing.

• Plugin marketplace: certified device packages at 20% commission, plus integration/training services.

• No mandatory subscription or per-user pricing in Community.

5) Global Go-to-Market via Free Channels

• Open-source core on GitHub with strong docs and SEO for “Modbus to MQTT” and “S7 to OPC UA”.

• Ready images on Docker Hub and GitHub Container Registry, a Home Assistant add-on, and Node-RED node.

• YouTube: real-device connection tutorials, live streams, and a free simulation lab.

• OT/IoT communities: Reddit, LinkedIn, Discord, Hacker News, automation groups.

• Free integration partnerships with Grafana, InfluxDB, Timescale, Node-RED.

• Free certification for integrators, with referral commission on paid deals.

• UI and docs in Arabic, English, Spanish, German, Portuguese, Chinese.

• University initiatives, hackathons, and graduation projects using simulators.

6) Risks (Legal and Technical)

Legal:

• Use protocol names/trademarks descriptively only, without logos or implied official endorsement.

• Trademark search for the new name before launch.

• Implement protocols in a Clean Room without copying code or protected docs.

• Comply with licenses, issue an SBOM, review patents and export controls.

• Clear disclaimer for critical/safety systems; contractual clauses limiting liability.

• GDPR and data sovereignty compliance, especially in cloud deployment.

Technical:

• Device version diversity and abnormal protocol behavior; test lab and compatibility matrix required.

• OT security: network segmentation, read-only default, mTLS, secrets management, signed plugins.

• Edge resource limits, latency, and reliability during outages.

• Complexity of upgrades, rollback, and high availability.

• Supply chain security: release signing, vulnerability scanning, dependency review.

• Support burden and edge-case docs; avoid unrealistic time promises.

7) Proposed Name and Tagline

Proposed name: Rafid Edge

Tagline: Connect any industrial device to one network in minutes, with no mandatory cloud and no vendor lock-in.
