Lumis — Full Project Plan

Draw, move, run — a simple, fast 2D media experience in one line.

Full implementation plan for a new digital project: idea, audience, product, revenue model, rollout, and risks. Under construction, not yet launched.

An original software product plan in 2D media and game development

1) Target Audience

• Individual developers and small studio teams (1–10 people) building interactive 2D games and applications with modern C++.

• Students and beginners in game programming, animation, and interactive applications.

• Developers who need a light library "not a full engine" to build educational tools, visual experiments, or interactive demos.

• Indie developers looking for a free starting point that supports Windows, macOS, Linux, and the web via WebAssembly.

2) Differentiators (why choose our product)

• Unified, simple C++17/20 interface: window, graphics, audio, input, and light networking — one naming style, one design mindset.

• Built-in export to the web via WebAssembly from the same codebase, without rewriting.

• Hot Reload for scripts and assets at runtime to speed up the development cycle.

• Optional modules: load only what you need (graphics, audio, simple physics) to cut binary size and memory.

• Free helper tools: a simple project generator, a light asset editor, and interactive documentation with ready-to-run examples.

• A clear license allowing commercial use for small teams, with no fees to start.

3) Scope of the First Release (at most 8 tasks)

1. 2D graphics core: window, shapes, text, images, and high-performance draw Batches.

2. Audio system: playing effects and music with multi-channel control and fading.

3. Input handling: keyboard, mouse, touch, and gamepads behind a unified interface.

4. Cross-platform layer: Windows, macOS, Linux, and WebAssembly.

5. Hot reload of assets and scripts at runtime.

6. Project generator and CLI to scaffold a ready-made project and build it fast.

7. Full documentation and ready learning examples (small games, graphics demos, audio apps).

8. Simple package and dependency system for installing and managing the library via the command line.

4) Pricing and Revenue Model

• Free to start: core library under a commercially friendly license, free for individuals and teams up to a fixed annual revenue cap (e.g. $100,000).

• Pro (monthly/yearly subscription): for studio teams — priority support, advanced publishing tools, custom device exports, and performance dashboards.

• Enterprise (corporate license): dedicated support, integration consulting, and service level agreements (SLA) for large companies.

• Marketplace: a simple commission on sales of game templates and audio and graphics assets from third-party creators.

• Training and certifications: paid courses and official credentials for developers and educational institutions.

5) Global Launch Plan Using Free Channels

• GitHub: publish the source code with clear examples, in-repo docs, and quick responses to feedback.

• YouTube: a short English lesson series (plus other languages) building small games step by step.

• Twitter/X and LinkedIn: weekly updates, GIF clips of the resulting games, and user success stories.

• Reddit and game developer forums: sharing examples and solutions, and posting release news without noisy promotion.

• Discord: a developer community for support, plus small monthly coding challenges with symbolic prizes.

• University competitions and Hackathons: partnerships with CS departments to use the library in graduation projects and free events.

• Technical blog (SEO): comparison articles, tooling pieces, and fixes for common 2D game development problems.

6) Risks (legal and technical)

Legal:

• Securing a clear license compatible with derivative licenses and preventing trademark infringement of third parties.

• Respecting dependency library rights (such as zlib and OpenGL) and including their notices in the distribution.

• Clear privacy policies for the community channel and analytics platforms, if any.

Technical:

• Graphics behavior differences (OpenGL/Vulkan/Metal) across systems and Drivers.

• Complexity of exporting to WebAssembly for high performance, audio, and storage in the browser.

• Documentation and examples volume: too few ready examples reduces adoption, and too many interfaces increases maintenance.

• Dependencies that are sensitive to system libraries across releases and systems.

7) Proposed Name and Tagline

Proposed name: Lumis

Tagline: Draw, move, run — a simple, fast 2D media experience in one line.
