Vigilo — Plano de Projeto Completo

Executamos seu app em cada pull request, instalamos a causa raiz do bug em vez de chutar.

Plano de execução completo para novo projeto digital: ideia, público, produto, modelo de receita, plano de divulgação e riscos. Projeto em construção, ainda não lançado.

Plano do produto: Revisão de código por execução real (Runtime AI Review)

O problema: Análise estática lê o código e não o executa; ela descobre erros de sintaxe e ignora erros de comportamento: rota de requisição quebrada, botão que não funciona, fluxo de login quebrado, ou condição de borda que colapsa com dados reais. Resultado: jornada "rugular" para produção, alto retrabalho em cada relato.

1) Público-alvo

· Segmento · Tamanho · Dor principal · O que busca ·

· Times de engenharia (5–50 devs) em entregas diárias · Maior · PR reviews lentos, bugs comportamentais aparecem após merge · CI barra PR quebrado automaticamente com prova entregável ·

· Devs de SaaS e e-commerce · Grande · Churn e suporte caros por bugs em runtime · Cenários E2E gerados automaticamente a cada mudança ·

· Times de frontend/full-stack · Médio · Não há macOS/Windows que rode ambiente de produção localmente · Execução real em runner isolado e auditável ·

· QA manual · Pequeno · Repetição de casos manuais · Transformar exploração manual em cenários reexecutáveis ·

· Times distribuídos geograficamente (incl. mercados MENA) · Médio · Tempos de resposta longos entre regiões · Evidências visuais (vídeo + logs) dispensam reproduce local ·

Interno: Principalmente devs de empresas e produtos digitais (Dev/Full-stack), e com o tempo operadores de plataformas QA e times de release.

2) Diferenciais (por que escolher nosso produto)

1. Execução dentro do seu CI: roda em runner isolado (self-hosted) ou runner cloud que você escolhe — não subimos seu código para nuvem de terceiros. Resultado: mais privacidade, menos custo, compliance mais fácil.

2. Execução incremental: mapa de dependência entre rotas, componentes e ações, então só rodam cenários afetados pela mudança — corte drástico de custo e tempo contra rodar tudo sempre.

3. Pacote de evidências verificável: vídeo WebM + logs de console + aba de rede + snapshots DOM + stack traces com números de linha, arquivos e seletores precisos — relatório pronto para virar ticket de suporte ou bug.

4. Reprodução determinística: seed fixo + simulação de tempo/rede/timezone + pin de versões ⇒ mesma falha repete com mesmos números, sem flakiness aleatório.

5. Nativo de CI, não plataforma à parte: saídas SARIF e JUnit + comentário automático no PR + opção de bloquear merge via Branch Protection. Não pede para o time mudar hábitos.

6. Flexibilidade de custo: BYO-LLM (sua chave) + modo "sem LLM" para cenários existentes + teto claro de tokens e duração por execução.

7. Core open-source com licença permissiva + versão enterprise self-hosted: grátis para sempre para projetos abertos, e vendível para empresas que proíbem SaaS externo.

8. Design do zero: arquitetura independente (CLI + Agent + Adapter layer), identidade visual nova, e modelo de interação (Evidence-first) não copiado de nenhum outro produto.

3) Escopo do v1 (máx. 8 tarefas)

1. CLI + GitHub Action / GitLab CI: comando único `vigilo run --pr 128` roda a checagem dentro de runner isolado, com flag `--local` para rodar na máquina do dev.

2. Ambiente de execução seguro: container efêmero sem segredos, recursos limitados, rede isolada por padrão (deny-all com whitelists), e teardown automático após execução.

3. Geração de cenários a partir do PR: análise do diff + descrição do PR + estrutura do projeto (openapi/nomes de telas) para gerar passos de navegação executáveis (driver estilo Playwright escrito do zero).

4. Agente explorador (Budgeted Explorer): navega UIs desconhecidas com orçamento de tempo/tokens definido, descobre rotas quebradas que nenhum cenário cobre.

5. Pacote de evidências: gravação de vídeo + logs + rede + snapshots DOM + traces, empacotados como arquivo comprimido com versão navegável localmente.

6. Localização precisa da falha: vincula stack trace a números de linha + reprodução copiável (comandos/passos/dados) em vez de "não foi possível executar".

7. Integração CI: SARIF + JUnit + comentário no PR + bloqueio de merge + re-run gate para flakiness.

8. Reprodução determinística + medição: seed/mock de tempo e rede, baseline report para comparar diffs, e painel leve dentro do PR (custo, duração, nº de checagens afetadas).
