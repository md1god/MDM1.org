Nabda — plan de proyecto completo

Tu fitness y nutrición en tu casa, con tus datos y total libertad.

Plan de ejecución completo para un nuevo proyecto digital: la idea, el público, el producto, el modelo de ingresos, el plan de difusión y los riesgos. El proyecto está en construcción y aún no se ha lanzado.

Plan de producto: plataforma abierta para el seguimiento de la forma física, la nutrición y el peso (autoalojamiento primero)

1) Público objetivo

• Personas preocupadas por la privacidad que rechazan vincular sus datos de salud a servidores comerciales cerrados.

• Comunidades de autoalojamiento y software libre (homelab, r/selfhosted).

• Entrenadores físicos y nutricionistas que necesitan un sistema personalizable para sus clientes sin tarifas excesivas.

• Equipos y clínicas pequeñas que quieren los datos en su propia infraestructura con cumplimiento legal.

2) Puntos de diferenciación (por qué elegir nuestro producto)

• Los datos son propiedad del usuario: exportación completa en formatos abiertos (JSON/CSV) e importación fluida, sin cautividad de datos.

• Funciona sin internet: aplicación web progresiva (PWA) que funciona offline y sincroniza después.

• Arquitectura ligera: un solo contenedor Docker + PostgreSQL, ejecutable en un equipo doméstico o un VPS pequeño.

• API primero: interfaz REST documentada y sandbox, con soporte de integración con relojes inteligentes mediante protocolos abiertos.

• Personalización sin código: editor de rutinas de ejercicios con arrastrar y soltar, y soporte RTL y traducción completa desde el primer día.

• Gratis de verdad para empezar: el núcleo libre sin límites de funciones, y los ingresos provienen de los servicios, no de bloquear lo básico.

3) Alcance de la primera versión (máximo 8 tareas)

1. Registro de ejercicios diarios y creación de rutinas de entrenamiento flexibles (series/repeticiones/pesos).

2. Biblioteca de ejercicios ampliable con etiquetas de músculos y equipamiento.

3. Seguimiento del peso y las medidas corporales con gráficos temporales.

4. Seguimiento de la nutrición: calorías + macros + base de alimentos comunes editable.

5. Aplicación web + PWA para móvil con funcionamiento sin conexión y sincronización.

6. REST API documentada + Webhooks + sistema de complementos (plugins).

7. Varios usuarios, roles y permisos, y vinculación de un entrenador con sus clientes.

8. Exportación/importación completa de datos + copia de seguridad cifrada y comando único de configuración.

Stack técnico propuesto: Go o Python para el backend, PostgreSQL, interfaz Next.js/React, contenedores Docker, documentación OpenAPI.

4) Precios y modelo de ingresos

• Versión libre (autoalojamiento): todas las funciones esenciales gratis para siempre, licencia libre que impide la reclausura comercial.

• Nube gestionada (Freemium): capa gratuita con un límite de almacenamiento sencillo, luego planes mensuales (por ejemplo 5$ / 10$ / 20$) para la sincronización automática, las copias de seguridad y el soporte.

• Plan para equipos/clínicas: suscripción según el número de usuarios + inicio de sesión único (SSO) + informes.

• Soporte y consultoría + Marketplace de complementos de pago (los desarrolladores conservan un porcentaje).

• Principio: gratis para empezar, y se paga por la comodidad y el mantenimiento, no por las funciones básicas.

5) Plan de difusión global con canales gratuitos

• Publicación en GitHub con un README sólido, imágenes explicativas y demo en directo.

• Inclusión en listas como awesome-selfhosted, Awesome Privacy y AlternativeTo.

• Lanzamientos simultáneos en Hacker News, Product Hunt y Reddit (r/selfhosted, r/QuantifiedSelf, r/opensource).

• Contenido técnico: artículos sobre la "propiedad de los datos de salud" en Dev.to, Hashnode y canales pequeños de YouTube.

• Comunidades abiertas: Lemmy, Mastodon y Discord, con un programa de colaboradores y recompensas simbólicas.

• Arabización y traducción comunitaria mediante Weblate para abrir nuevos mercados sin presupuesto de marketing.

6) Riesgos (legales y técnicos)

Legales:

• Privacidad de los datos de salud: cumplimiento del GDPR y similares, cifrado en tránsito y en reposo, y una política de privacidad clara.

• Exención de responsabilidad médica explícita (el producto no es una herramienta de diagnóstico ni de tratamiento).

• Compatibilidad de la licencia libre y prohibición de reclausura comercial, y revisión de patentes en los nombres y logotipos.

• No presentar afirmaciones médicas de marketing no demostradas.

Técnicos:

• Conflictos de sincronización entre varios dispositivos offline, resueltos mediante CRDT o marcas
