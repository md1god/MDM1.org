SpecWeave — Plan completo del proyecto

Convierte cualquier especificación en una suite de pruebas de navegador viva que falla antes que los usuarios.

Plan de ejecución completo: idea, audiencia, producto, modelo de negocio, lanzamiento y riesgos. Proyecto en construcción, sin lanzar.

1) Público objetivo

• Fundadores de apps de IA (Cursor, Bolt, Lovable, v0) lanzan 3-5 versiones/semana sin QA y descubren fallos en producción.

• Indie hackers con < $10k/mes, 1-3 personas, sin presupuesto para Cypress Cloud/BrowserStack.

• Agencias MVP (5-20 empleados) entregan 4-8 proyectos/mes; necesitan prueba visible de specs completas.

• PMs early-stage (5-30 empleados) escriben PRD en lenguaje natural, no leen TypeScript.

• Mantenedores OSS (10k+ estrellas) quieren cobertura E2E sin mantenimiento manual.

• Equipos "vibe coding" (2-4 devs) usan Claude Code/Copilot Workspace y quieren puerta de calidad automática en PR.

2) Diferenciadores

• Spec-first: cada prueba deriva de comportamiento declarado (spec/PR/descripción) con mapping spec→test.

• Free-to-start real: 50 ejecuciones/mes gratis sin tarjeta en repos públicos; competidores piden $39-99/mes desde el día 1.

• Informes de fallo legibles: screenshot + video + "Paso 3/7: botón de envío deshabilitado" en vez de stack trace; enlace (7 días).

• Comentarios PR automáticos: GitHub App publica ✅/❌ + resumen + enlace, sin CI.

• Sin lock-in: exportar como Playwright .spec.ts (100% propiedad). Self-host runner (MIT) opcional.

• Mocks deterministas: grabar HAR una vez, reproducir byte-identical → flakiness < 2% (vs 8-15% típico).

3) Alcance v1 (8 tareas)

1. GitHub App + webhook PR (instalación + HMAC) — 5 días

2. Spec parser: markdown/PR body/texto → plan JSON (pasos, selectores, aserciones) — 7 días

3. Browser runner: Playwright en contenedores con replay HAR — 6 días

4. Informe de fallo: screenshots, video, pasos de repro, enlace — 4 días

5. Bot comentarios PR: resumen pass/fail + enlace — 3 días

6. Cuota gratis + Stripe (50 runs/mes) — 4 días

7. Dashboard: proyectos + historial + exportar .spec.ts — 4 días

8. Seguridad: allowlist de dominios + atestación — 3 días

Total ~36 días (MVP 6 semanas, 1 dev + 0.5 diseñador).

4) Precios y modelo de ingresos

• Free: 50 ejecuciones/mes, 1 proyecto, repos públicos, retención 7 días. Objetivo: 1.000 usuarios en 90 días.

• Starter $19/mes: 500 ejecuciones, 5 proyectos, repos privados, retención 30 días.

• Pro $49/mes: 2.000 ejecuciones, proyectos ilimitados, runners prioritarios, retención 90 días.

• Team $149/mes: 10.000 ejecuciones, SSO (SAML), audit log, 5 seats. Enterprise: personalizado (SOC2, on-prem, SLA 99.9%).

• Overage: $0.05/ejecución tras cuota (basado en uso). Coste: ~$0.012/ejecución → margen bruto ~76% en Pro.

• Objetivo MRR: $1.700/mes en mes 6 (50 de pago × $34); $8.500/mes en mes 12 (300 de pago).

5) Plan global de lanzamiento con canales gratuitos

• Lanzamiento Product Hunt (martes 12:01 PT) + 50 upvotes semilla; objetivo Top 5 del día.

• Show HN: "SpecWeave: turn a PR description into a browser test suite" — demo Loom 3 min.

• Reddit: r/SideProject, r/webdev, r/QualityAssurance (1 post/semana, value-first).

• Twitter/X: 3 hilos/semana (GIFs demo antes/después) + participación en comunidades Cursor/Bolt/Lovable.

• Discord: servidores Cursor, Bolt, Lovable, v0 — responder preguntas, mención suave. Dev.to/Hashnode: 2 tutoriales/mes.

• GitHub Marketplace (gratis) + insignia "Works with GitHub" → descubrimiento orgánico. SEO + YouTube + outreach frío: 10 posts/trimestre, tutorial 5 min, 200 fundadores/semana por DM en X (3% respuesta).

6) Riesgos (legales y técnicos)

• Legal: probar sitios no propios → atestación + allowlist de dominios + ToS. GDPR: borrar HAR (PII) en 30 días, DPA disponible. Licencia MIT para runner.

• Legal: "las pruebas generadas por IA pueden omitir" → disclaimer + gate de revisión humana antes del merge (bloqueo auto-merge opt-in).

• Técnico: pruebas flaky por contenido dinámico → replay HAR + reintento 2× + flag de cuarentena (desactivación automática si flaky > 3 seguidas).

• Técnico: coste LLM/contenedores → cachear planes por hash de spec; reutilizar entre PRs; límite 5 min.

• Técnico: hallucination en selectores → recomendar data-testid + fallback texto/rol; confianza < 0.7 → revisión humana.

• Técnico: escape sandbox + límites tasa API GitHub → contenedores gVisor, sin red saliente excepto permitida, efímeros; GitHub App (5000 req/hr) + cola + backoff.

7) Nombre propuesto y eslogan

Nombre propuesto: SpecWeave
