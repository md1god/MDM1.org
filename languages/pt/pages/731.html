AriaForge — Plano completo do projeto

Escaneie seu site, obtenha correções prontas para copiar e acompanhe a conformidade automaticamente.

Plano de execução completo para um novo projeto digital: ideia, público, produto, modelo de receita, plano de lançamento e riscos. O projeto está em construção e ainda não foi lançado.

1) Público-alvo

• Fundadores de sites SaaS/no-code (Webflow, Bubble, Framer) com equipes de 5–50 funcionários e receita de 10k–200k$ mensais; 40% de suas páginas apresentam problemas de acessibilidade.

• Agências de desenvolvimento web (20–200 funcionários) que precisam de relatórios de conformidade para seus clientes (ADA/WCAG 2.2 AA).

• Gerentes de produto/marketing em lojas Shopify que querem evitar processos ADA (acordo médio de 25k$).

• Desenvolvedores independentes usando v0/Bolt/Lovable para criar interfaces com IA.

• Instituições de ensino e sem fins lucrativos que precisam de conformidade WCAG 2.2 AA nas páginas de inscrição.

• Designers do Figma que querem verificar acessibilidade antes de escrever código.

2) Diferenciais (por que escolher nosso produto)

• Correções prontas para copiar (diff para React/Vue/HTML), não apenas um relatório; reduz o tempo de correção de 8 horas para 15 minutos.

• Ordenação por risco jurídico + impacto no usuário (processos ADA Title III, leitores de tela).

• Camada gratuita: 5 verificações/mês, 10 páginas cada, sem cartão de crédito, sem marca d'água.

• IA treinada em falhas reais de WCAG do Common Crawl; precisão de alt text de 95%.

• Monitoramento contínuo via GitHub Action + alertas no Slack; detecção de ARIA fabricado em código de IA.

• Opção on-prem/GDPR, sem armazenamento de PII, respeito ao robots.txt.

3) Escopo da primeira versão (máximo 8 tarefas)

1. Motor de verificação de URL (Playwright + axe-core) para detectar 50+ regras.

2. Gerador de correções por IA (LLM) para alt text, labels, contraste, ordem de foco, nomes de botões.

3. Painel web com lista de problemas ordenada + visualizador de diff.

4. Cadastro free tier + autenticação por magic link.

5. Faturamento Stripe para Starter/Pro/Team.

6. GitHub Action para verificação em CI.

7. Relatório de monitoramento semanal por e-mail/Slack.

8. Documentação + tutorial de onboarding (5 passos).

4) Preços e modelo de receita

• Free: 5 verificações/mês, 10 páginas, correções básicas.

• Starter 19$/mês: 50 verificações, 100 páginas, correções por IA, monitoramento de um site.

• Pro 79$/mês: verificações ilimitadas, 500 páginas, 5 assentos de equipe, integração com CI.

• Team 249$/mês: SSO, on-prem, SLA, suporte dedicado.

• Enterprise: preço sob medida (contrato anual).

• Receita: 60% Pro, 25% Team, 15% complementos (relatórios de auditoria em PDF por 9$).

• Meta: 1000 usuários free → 5% de conversão = 50 pagantes = ~3950$ MRR no mês 6.

• Tutoriais no YouTube (acessibilidade para sites gerados por IA) 1/semana.

• Artigos no Dev.to/Hashnode (SEO: "WCAG scanner free", "accessibility checker AI").

• Parcerias com comunidades no-code (fórum Webflow, fórum Bubble).

• Wrapper open-source do axe-core no GitHub (meta: 1000 stars).

6) Riscos (jurídicos e técnicos)

• Jurídico: processos ADA; isenção de responsabilidade (a ferramenta não é certificação jurídica); WCAG não é obrigatório em todas as jurisdições; evitar alegação de "compliant".

• Privacidade: verificar sites de terceiros pode capturar PII; respeito ao robots.txt, rate limiting, retenção de 30 dias.

• Técnico: falsos positivos ~15% do axe-core; correções por IA podem quebrar a UI; revisão humana + pré-visualização obrigatórias.

• Desempenho: verificar sites grandes é custoso; fila + cache + limite de 500 páginas.

• Concorrência: AudioEye/accessiBe/UserWay; diferenciação via patches prontos para desenvolvedores.

• Drift de modelos: providers mudam; camada de abstração + fallback.
