KhaytGrid — plan de projet complet

Nous tissons les données énergétiques publiques en un tissu unique prêt pour l’analyse et la vérification.

Plan complet : idée, public, produit, revenus, déploiement, risques. Projet en construction, non lancé.

1) Public cible

• Chercheurs énergie/climat/économie : données interopérables et citables.

• Journalistes d’investigation : chiffres fiables et sourcés.

• Décideurs et régulateurs : comparaisons installations, marchés, prix.

• ONG, think tanks, étudiants : alternative gratuite aux bases commerciales.

• Analystes, planificateurs : API et sorties propres.

• Problème : données publiques dispersées en milliers de fichiers, PDF et pages web aux noms, identifiants et formats contradictoires ; nettoyage et vérification trop lents.

2) Points différenciateurs

• Une source par chiffre : fichier, date, confiance, transformations.

• Identifiants unifiés (établissements, installations, générateurs) ; cas ambigus revus.

• Prêt pour l’analyse : Parquet/CSV, SQL, API et notebooks, sans nettoyage.

• Extraction PDF hybride : règles déterministes + modèles de langage + revue humaine.

• Instantanés reproductibles : empreinte et version par jeu.

• Gratuit au départ, sans verrouillage : schéma et connecteurs ouverts ; paiement pour extension, pas l’accès.

• Code et identité originaux, sans copie d’un produit.

3) Périmètre de la première version (8 tâches maximum)

1. Canonical Schema ouvert : établissements, générateurs, installations, combustibles, capacité, production, émissions, prix.

2. Connecteurs EIA-860/923, FERC Form 1 et files d’appariement de trois marchés ISO, MAJ mensuelle.

3. Pipeline PDF : extraction de tableaux, validation, confiance, revue humaine.

4. Entity Resolution et identifiant stable par établissement/installation/générateur.

5. Snapshots signés avec traçabilité de chaque champ et transformation.

6. Interface web, API REST, endpoint SQL, client Python, export Parquet/CSV.

7. Qualité et alertes : sources, schémas, valeurs aberrantes.

8. Notebooks Jupyter et modèles pour presse, recherche, politiques.

4) Tarification et revenus

· Offre · Prix · Inclus ·

· Free · 0 $ · Données de base, MAJ mensuelle, 10 000 requêtes API/mois, export 100 Mo, notebooks et ressources ·

· Pro · 29 $/mois · MAJ quotidienne, 1 million de requêtes API, export 10 Go, alertes, requêtes enregistrées, espaces privés ·

· Team · 149 $/mois · 10 sièges, SSO, projets partagés, journal d’audit, 5 millions de requêtes API ·

· Enterprise · dès 12 000 $/an · Connecteurs personnalisés, privé/on-prem, SLA, formation, support prioritaire ·

Revenus annexes : recherche/analyse sur mesure, parrainage, subventions et partenariats. Données de base gratuites ; aucune vente de données personnelles.

5) Déploiement mondial, canaux gratuits

• Phase 1 (0–6 mois) : États-Unis, Canada, via référencement des pages installations, établissements et prix.

• Phase 2 (6–18 mois) : Royaume-Uni, UE, Australie : packs de juridiction et schémas extensibles.

• Phase 3 (18 mois+) : Amérique latine, Asie, Afrique : partenariats locaux et documentation traduite.

Canaux gratuits :

• GitHub ouvert : schéma, connecteurs, documentation et licence claire.

• Jeux de données sur Hugging Face, Kaggle et Zenodo avec DOI citable.

• Contenu pédagogique, SEO : guides, exemples, comparaisons installations/prix.

• Universités, écoles de journalisme, centres de données non lucratifs, ateliers gratuits.

• Discord, questions mensuelles, ambassadeurs étudiants/chercheurs.

• PyData, NICAR, Open Data Day et hackathons énergie.

• YouTube, newsletter, traductions arabe, espagnol, français, portugais.

6) Risques juridiques et techniques

Juridiques :

• Conditions des sources, robots.txt, débits ; API officielles et téléchargements agrégés.

• Licence vérifiée par source ; faits publiés avec lien, sans copier les documents.

• GDPR/CCPA, minimisation des données personnelles, aucune vente.

• Avertissement clair, corrections, journal des modifications.

• Vérification de la marque et du nom avant lancement.

Techniques :

• Erreurs PDF et hallucinations des modèles : validation, confiance, revue humaine, régression.

• Changements de schémas : surveillance automatique, versions par connecteur.

• Mauvais appariement : seuils prudents, revue, annulation possible.

• Volume/coût : stockage colonnaire, MAJ incrémentielle, cache.

• Abus API : clés, quotas, limites de débit.

• Reproductibilité : instantanés immuables, empreintes, sauvegardes.

7) Nom et accroche

Nom proposé : KhaytGrid

Accroche : Nous tissons les données énergétiques publiques en un tissu unique prêt pour l’analyse et la vérification.
