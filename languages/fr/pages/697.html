Kanvia — Plan de projet complet

Déplacez les cartes de votre équipe de l'idée à la réalisation sans désordre ni complexité.

Plan d'exécution complet pour un projet numérique (idée, audience, produit, revenus, diffusion, risques). En construction.

1) Public cible

• Petites équipes (3–15) sur GitHub/GitLab, lassées de Jira (ex. SaaS 7 pers., 4 h/sem.).

• Créateurs indépendants (indie makers) : idées+bugs au même endroit (ex. dev solo, 40 idées Notion).

• Agences marketing/dev (5–20 projets clients) : tableau par client sans permissions complexes.

• Équipes non techniques (marketing, ops) : Trello désorganisé, Jira lourd ; 2–3 tableaux, 50 cartes.

• Équipes distantes multi-fuseaux : 12 membres, mises à jour asynchrones, historique clair.

• Maintainers open source : tri rapide issues/feature requests (50+/sem.).

2) Points forts

• Un seul flux idées/problèmes + boîte de tri (Inbox) : moins de basculement (Notion+Trello+GitHub Issues), ~30% temps gestion économisé.

• « Pas maintenant » (Not now) avec réapparition auto après 14 j. : évite backlog et pourrissement des cartes (stale cards).

• Sans configuration : tableau prêt en 90 s, sans champs obligatoires ni workflows complexes.

• Vrai free-to-start : cartes illimitées sur 1 tableau, 5 utilisateurs ; paiement pour tableaux multiples et automatisation.

• PWA léger (offline-first) : mobile, <100 ms, bundle <200 KB.

• Self-host via Docker + export JSON/CSV en un clic : pas de lock-in, données possédées.

3) Périmètre v1

1. Modèle de données : boards, columns (Inbox/To do/Doing/Done/Not now/Closed), cards, tags, assignments, comments.

2. Auth : magic link email + passkey, un compte, plusieurs utilisateurs, rôles (owner/member/viewer).

3. UI Kanban : drag-and-drop entre colonnes, modal de carte, Markdown, @mentions, pièces jointes (limite 10 MB).

4. Boîte de tri (Triage) : nouveaux éléments dans « Inbox » ; déplacement en un clic vers un tableau ou « Not now » avec date de réapparition.

5. Recherche et filtres : full-text sur les cartes, par tag/assignee/status ; filtres sauvegardés, vue « My work ».

6. Notifications : in-app + email digest quotidien/hebdomadaire ; web push optionnel (VAPID).

7. Export/import JSON+CSV + lien tableau lecture seule (public read-only) avec contrôles de confidentialité.

8. Déploiement Docker + docs + tests (unit + e2e smoke) + endpoint health check.

4) Tarification et revenus

• Free : 1 tableau, 5 utilisateurs, cartes illimitées, 100 MB, 7 j. d'historique.

• Starter : 6 $/utilisateur/mois — tableaux illimités, 5 GB, automatisation (rules), intégrations (GitHub, Slack, Zapier), support prioritaire.

• Team : 12 $/utilisateur/mois — SSO (SAML/OIDC), audit log, permissions avancées, 50 GB, SLA 99.9 %.

• Enterprise : tarif sur demande — on-prem, support dédié, SLA personnalisé.

• Self-host : communauté gratuite (Docker) + licence support 299 $/an (updates + email prioritaire).

• Modèle de revenus : conversion freemium 3–5 % ; upsell à 20+ cartes/sem. ou 2e tableau ; -20 % annuel. Ex. : 10 000 gratuits → 400 payants → ~120 k$ MRR.

5) Diffusion (canaux gratuits)

• GitHub : core ouvert (MIT) + docs + déploiement en un clic (Docker/Railway/Fly.io) ; objectif 500 étoiles/30 j.

• Contenu SEO : 2 articles/sem. (EN + ES) sur « simple kanban for small teams », « jira alternative for startups » ; études de cas 500–800 mots.

• Communautés : Reddit (r/startups, r/projectmanagement), Hacker News Show HN, IndieHackers ; 3 commentaires utiles/sem., sans spam.

• Vidéo : YouTube 1 vidéo/sem. (démos 60–120 s) + Shorts/TikTok ; intégration dans la doc.

• Intégrations : marketplace GitHub Actions, Zapier/Make listing ; freemium apporte la découverte (objectif 1 000 installations/90 j.).

• Localisation : EN d'abord, puis ES/PT/FR/AR via Crowdin ; support RTL dès le départ.

6) Risques

• Juridique — marque : nom unique, recherche USPTO/EUIPO avant lancement ; budget 500 $.

• Juridique — confidentialité : GDPR/CCPA ; DPA, suppression des données sous 30 j., hébergement EU possible.

• Juridique — PI : code entièrement original ; MIT pour le core ; provenance documentée (no copied assets).

• Technique — performance : SQLite par défaut en self-host, Postgres en cloud ; index boardid, status ; test de charge 10 k cartes/tableau.

• Technique — synchronisation : UI optimiste + versioning (last-write-wins with conflict notice) ; test des éditions simultanées.

• Technique — sécurité : OWASP top 10, analyse des dépendances (Dependabot), CSP, limitation de débit sur l'auth ; 2FA.

7) Nom et slogan

Kanvia — Déplacez les cartes de votre équipe de l'idée à la réalisation sans désordre ni complexité.
