Qirtas — plan de projet complet

Nous transformons le Web en données propres, prêtes pour les agents d’IA, en une seule requête.

Plan d’exécution d’un projet numérique : idée, public, produit, modèle économique, diffusion et risques. Projet en construction.

Plan produit : plateforme d’extraction de données Web pour agents d’IA

1) Public cible

• Développeurs d’IA créant des agents (Agents) ou systèmes RAG et ayant besoin de contenu Web propre.

• Petites startups évitant de bâtir une couche de scraping et de traitement de zéro.

• Équipes d’analyse collectant régulièrement du contenu sur plusieurs sites.

• Agences d’automatisation et créateurs no-code (n8n, Make) cherchant une intégration prête.

• Chercheurs archivant pages et références en formats structurés.

2) Différenciation

• Gratuit réel : crédit mensuel permanent sans carte, suffisant pour l’essai et la petite production.

• Sorties prêtes : Markdown propre, JSON contraint par un Schema défini par l’utilisateur, captures d’écran au besoin.

• Conception native pour agents : Async Jobs, Webhooks, serveur MCP et SDK officiel, plutôt que le scraping classique.

• Soutien arabe et multilingue : RTL, diacritiques et pages multilingues.

• Coûts transparents : compteur par requête et cache réduisant appels répétés, facture.

• Conformité intégrée : robots.txt et politiques des sites respectés par défaut, journal d’audit par opération.

• Pas de verrouillage : export des données, normes ouvertes, auto-hébergement Enterprise.

3) Périmètre V1 (8 tâches maximum)

1. extract : URL vers Markdown propre, sans menus, publicités ni bruit.

2. extract avec schéma JSON pour champs précis (prix, titre, date…).

3. Rendu JavaScript via Headless Browser avec attente intelligente.

4. crawl limité pour explorer un site à une profondeur donnée et renvoyer les liens.

5. search pour trouver des pages puis extraire directement les meilleurs résultats.

6. Clés API, quotas et crédit, tableau de bord simple et historique de consommation.

7. Async Jobs + Webhooks + SDK initial (Python, TypeScript) + serveur MCP.

8. Cache, journalisation, nouvelle tentative automatique, documentation complète et exemples prêts.

4) Tarification et revenus

• Free : crédit mensuel fixe (ex. 500 opérations), débit limité, sans carte.

• Pay-as-you-go : à l’usage après le gratuit, par opération ou millier de pages.

• Starter / Growth : crédit supérieur, priorité, plages plus larges, tarif réduit.

• Enterprise : contrat, limites dédiées, SLA, facturation, auto-hébergement.

• Revenus additionnels : Templates avec commission ; interfaces payantes (captures, PDF, tableaux).

• Principes : crédit unifié, report limité, remise annuelle.

5) Diffusion mondiale par canaux gratuits

• SDK et CLI open source sur GitHub, exemples et README solide.

• Serveur MCP dans les annuaires MCP et boutiques d’outils pour agents.

• Documentation SEO, guides comparatifs et « comment faire » par cas d’usage.

• Lancement sur Product Hunt, Hacker News et Reddit (r/LocalLLaMA, r/MachineLearning), avec transparence.

• Intégrations gratuites : LangChain, LlamaIndex, n8n, Make, Zapier.

• Vidéos courtes sur YouTube, tutoriels sur dev.to et Medium.

• Discord et newsletter hebdomadaire : cas d’usage et mises à jour.

• Concours et hackathons universitaires, parrainage de Good First Issues open source.

6) Risques juridiques et techniques

Juridiques :

• Conditions des sites et droit d’auteur variables ; solution : robots.txt, usage acceptable, domaines exclus.

• Données personnelles (GDPR/CCPA) ; solution : collecte minimale, stockage court par défaut, outils de suppression.

• Responsabilité utilisateur sur le contenu extrait ; solution : conditions claires, usage autorisé.

• Risques régionaux variables ; solution : veille régulière et blocage souple.

Techniques :

• Anti-scraping, CAPTCHA, blocage d’IP ; solution : réseau diversifié, nouvelles tentatives, limites communiquées.

• Rendu JavaScript coûteux ; solution : cache intelligent, rendu léger si possible, limites claires.

• Extraction fragile après refonte ; solution : schémas flexibles, tests de surveillance, alertes.

• Prompt Injection et pollution ; solution : assainissement des sorties et marquage du contenu non fiable.

• Sécurité (SSRF, abus de quotas) ; solution : domaines bloqués, limites de débit, surveillance.

• Fiabilité et charge ; solution : files de traitement, supervision, reprise et disponibilité progressive.

7) Nom et slogan

Nom proposé : Qirtas (قِرطاس)

Slogan : Nous transformons le Web en données propres, prêtes pour les agents d’IA, en une seule requête.
