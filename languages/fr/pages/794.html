SpecWeave — plan de projet complet

Transformez toute spécification en une suite de tests navigateur vivants qui éclatent avant vos utilisateurs.

Projet numérique : idée, public, produit, revenus, diffusion, risques. En construction, non lancé.

1) Public cible 🎯

• Fondateurs d'apps AI (Cursor, Bolt, Lovable, v0) livrant 3-5 versions/semaine sans QA, pannes vues en production. Ex. : fondateur SaaS cassant le paiement après refonte.

• Indie hackers à < 10 k$/mois, 1-3 personnes, sans budget Cypress Cloud/BrowserStack.

• Agences MVP (5-20) livrant 4-8 projets/mois, devant prouver « les specs réalisées ».

• PMs early-stage (5-30) rédigeant des PRD en langage naturel, sans lire TypeScript.

• Mainteneurs OSS (10 k+ étoiles) voulant une couverture E2E sans maintenance manuelle.

• Équipes « vibe coding » (2-4 devs) sur Claude Code/Copilot Workspace voulant une porte qualité en PR.

2) Points de différenciation

• Spec-first : chaque test dérive d'un comportement déclaré (spec/PR/description) avec mapping spec→test. Ex. : « réinitialisation du mot de passe » → 3 étapes.

• Free-to-start réel : 50 exécutions/mois gratuites, sans carte, dépôts publics ; concurrents : 39-99 $/mois d'emblée.

• Rapports d'échec lisibles : capture + vidéo + « Étape 3/7 : bouton Envoyer désactivé » au lieu d'une stack trace ; partage par lien 7 j.

• Commentaires PR automatiques : GitHub App publie ✅/❌ + résumé + lien, sans CI.

• Sans lock-in : export en Playwright .spec.ts (100 % détenu) ; runner auto-hébergé (MIT) en option.

• Mocks déterministes : HAR enregistré une fois, relecture byte-identical → flakiness < 2 % (vs 8-15 %).

3) Périmètre de la première version (8 tâches)

1. GitHub App + webhook PR (installation + HMAC) — 5 j

2. Parseur de spec : markdown/corps PR/texte → plan JSON (étapes, sélecteurs, assertions) — 7 j

3. Runner navigateur : Playwright en conteneurs, relecture HAR — 6 j

4. Rapport d'échec : captures, vidéo, reproduction, partage — 4 j

5. Bot de commentaire PR : résumé réussite/échec + lien — 3 j

6. Quota Free + facturation Stripe (50 exécutions/mois) — 4 j

7. Tableau de bord : projets, historique, export .spec.ts — 4 j

8. Sécurité : liste blanche de domaines + attestation d'autorisation — 3 j

Total ~36 j (MVP 6 semaines, 1 dev + 0,5 designer).

4) Tarification et modèle de revenus

• Free : 50 exécutions/mois, 1 projet, dépôts publics, rétention 7 j. Objectif : 1 000 utilisateurs en 90 j.

• Starter 19 $/mois : 500 exécutions, 5 projets, dépôts privés, rétention 30 j.

• Pro 49 $/mois : 2 000 exécutions, projets illimités, runners prioritaires, rétention 90 j.

• Team 149 $/mois : 10 000 exécutions, SSO (SAML), audit log, 5 sièges. Enterprise : sur mesure (SOC2, on-prem, SLA 99,9 %).

• Dépassement : 0,05 $/exécution (usage-based). Coût : ~0,012 $/exécution → marge brute ~76 % sur Pro.

• MRR visé : 1 700 $/mois au mois 6 (50 payants × 34 $) ; 8 500 $/mois au mois 12 (300 payants).

5) Diffusion mondiale via canaux gratuits

• Product Hunt (mardi 12:01 PT) + 50 upvotes ; objectif Top 5.

• Show HN : « SpecWeave: turn a PR description into a browser test suite » — démo Loom 3 min.

• Reddit : r/SideProject, r/webdev, r/QualityAssurance (1 post/semaine, valeur d'abord).

• Twitter/X : 3 threads/semaine (GIF avant/après) + communautés Cursor/Bolt/Lovable.

• Discord : Cursor, Bolt, Lovable, v0 — réponses et mention discrète. Dev.to/Hashnode : 2 tutoriels/mois.

• GitHub Marketplace (gratuit) + badge « Works with GitHub » → découverte organique. SEO + YouTube + cold outreach : 10 posts/trimestre, tutoriel 5 min, 200 fondateurs/semaine par X DM (3 %).

6) Risques (juridiques et techniques)

• Juridique : sites non possédés → attestation + liste blanche de domaines + ToS. GDPR : HAR (PII possible) supprimé sous 30 j, DPA disponible. Runner sous MIT.

• Juridique : « tests AI pouvant manquer des cas » → disclaimer + validation humaine avant merge (auto-merge bloqué par opt-in).

• Technique : tests instables (contenu dynamique) → relecture HAR + 2 essais + quarantaine (désactivation auto après > 3 échecs).

• Technique : coûts LLM/conteneurs → cache des plans par hash de spec, réutilisation entre PR, exécution limitée à 5 min.

• Technique : hallucinations de sélecteurs → data-testid recommandé + repli texte/rôle ; confiance < 0,7 → validation humaine.

• Technique : évasion de sandbox + limites API GitHub → conteneurs gVisor éphémères, réseau sortant limité à la liste blanche ; GitHub App (5000 req/h) + file + backoff.

7) Nom proposé et phrase marketing

Nom proposé : SpecWeave

Phrase marketing : Transformez toute spécification en tests navigateur vivants qui éclatent avant vos utilisateurs.
