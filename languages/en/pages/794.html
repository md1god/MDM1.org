SpecWeave — Complete Project Plan

Turn any spec into a live browser test suite that breaks before users do.

Complete execution plan for a new digital project: idea, audience, product, business model, launch plan, and risks. The project is under construction and not yet launched.

1) Target Audience

• AI app founders (Cursor, Bolt, Lovable, v0) shipping 3-5 releases/week without a QA team and discovering crashes in production. Example: a SaaS founder built a dashboard with Lovable and broke the payment flow after a refactor.

• Indie hackers with revenue < $10k/month, 1-3 people, no budget for Cypress Cloud/BrowserStack.

• MVP agencies (5-20 employees) delivering 4-8 projects/month and needing visual proof that "specs are done."

• PMs at early-stage companies (5-30 employees) writing PRDs in natural language and not reading TypeScript.

• OSS maintainers (10k+ stars) wanting E2E coverage without manual maintenance.

• "vibe coding" teams (2-4 developers) using Claude Code/Copilot Workspace wanting an automatic quality gate in PRs.

2) Differentiators

• Spec-first: every test derived from declared behavior (spec/PR/description) with spec→test mapping. Example: "Password reset" → 3 steps.

• Truly free-to-start: 50 runs/month free without a card for public repos; competitors charge $39-99/month from day one.

• Readable failure reports: screenshot + video + "Step 3/7: submit button disabled" instead of stack trace, share via link (7 days).

• Automatic PR comments: GitHub App posts ✅/❌ + summary + report link, no CI setup.

• No lock-in: export tests as Playwright .spec.ts (100% owned). Optional self-host runner (MIT).

• Deterministic mocks: record HAR once, replay byte-identical → flakiness < 2% (vs 8-15% typical).

3) First release scope (8 tasks)

1. GitHub App + webhook on PR (install flow + HMAC verify) — 5 days

2. Spec parser: markdown/PR body/plain text → JSON test plan (steps, selectors, assertions) — 7 days

3. Browser runner: Playwright in containers with HAR replay — 6 days

4. Failure report page: screenshots, video, repro steps, share link — 4 days

5. PR comment bot: pass/fail summary + link — 3 days

6. Free tier quota + Stripe billing (50 runs/mo free) — 4 days

7. Dashboard: projects + run history + export .spec.ts — 4 days

8. Safety: domain allowlist + user authorization attestation — 3 days

Total ~36 days (MVP in 6 weeks, 1 developer + 0.5 designer).

4) Pricing and revenue model

• Free: 50 runs/month, 1 project, public repos, 7-day retention. Goal: 1,000 users in 90 days.

• Starter $19/month: 500 runs, 5 projects, private repos, 30-day retention.

• Pro $49/month: 2,000 runs, unlimited projects, priority runners, 90-day retention.

• Team $149/month: 10,000 runs, SSO (SAML), audit log, 5 seats. Enterprise: custom (SOC2, on-prem, SLA 99.9%).

• Overage: $0.05/run after quota (usage-based). Cost: ~$0.012/run → gross margin ~76% on Pro.

• MRR goal: $1,700/month month 6 (50 paid × $34); $8,500/month month 12 (300 paid).

5) Global launch plan via free channels

• Product Hunt launch (Tuesday 12:01 PT) + 50 upvotes seed; goal Top 5 of day.

• Show HN: "SpecWeave: turn a PR description into a browser test suite" — 3-min Loom demo.

• Reddit: r/SideProject, r/webdev, r/QualityAssurance (1 post/week, value-first).

• Twitter/X: 3 threads/week (before/after demo GIFs) + engage Cursor/Bolt/Lovable communities.

• Discord: Cursor, Bolt, Lovable, v0 servers — answer questions, soft mention. Dev.to/Hashnode: 2 tutorials/month.

• GitHub Marketplace listing (free) + "Works with GitHub" badge → organic discovery. SEO + YouTube + cold outreach: 10 posts/quarter, 5-min tutorial, 200 founders/week via X DM (3% reply).

6) Risks (legal and technical)

• Legal: testing sites the user doesn't own → attestation + domain allowlist + ToS. GDPR: delete HAR (may contain PII) within 30 days, DPA available. MIT license for runner.

• Legal: "AI-generated tests may miss" → disclaimer + human review gate before merge (opt-in auto-merge block).

• Technical: flaky tests due to dynamic content → HAR replay + retry 2× + quarantine flag (auto-disable flaky > 3 consecutive).

• Technical: LLM/containers cost → cache test plans by spec hash; reuse across PRs; cap 5-min run.

• Technical: selector hallucination → require data-testid recommendation + fallback to text/role; confidence < 0.7 → human review.

• Technical: sandbox escape + GitHub API rate limits → gVisor containers, no outbound network except allowlisted, ephemeral; GitHub App (5000 req/hr) + queue + backoff.
