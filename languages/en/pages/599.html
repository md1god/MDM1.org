Mirsad — Complete Project Plan

The browser that understands web pages, executes tasks reliably, and documents every step.

Plan for a digital project: idea, audience, product, revenue, launch, risks. Under construction; not launched.

Product plan: browser-agent platform

1) Target audience

• AI Agents developers: agents running tasks on real sites (booking, purchasing, forms, order tracking).

• QA and automation: replayable, auditable agents instead of fragile test scripts.

• Data extraction and Ops/RPA: structured data from dashboards or sites without an API.

• Regulated companies: cannot send page data to a third-party cloud.

• Agencies and freelancers: repetitive client tasks at low cost.

2) Differentiators (why us)

· Pillar · Offer ·

· Privacy first · Local or client-network by default; page data and credentials stay there. ·

· Reliability · Full session recording (DOM snapshots + HAR + screenshots) and deterministic replay for diagnosis. ·

· Self-healing · Accessibility-tree selectors with fallbacks that repair themselves when the UI changes. ·

· Hybrid and controllable · Natural-language interface for quick tasks and typed SDK (TypeScript/Python) for precise control, without splitting the two worlds. ·

· Auditability · Signed step log: what was seen, decided, executed, and authorized, for review and compliance. ·

· Security · Sandbox, allowed-domain policies, human confirmation for sensitive actions, page content as untrusted input against Prompt Injection. ·

· Cost · Free open-source core, light resources, free start. ·

· Model neutrality · Any LLM (cloud or local), no vendor lock-in. ·

3) Scope of the first version (max 8 tasks)

1. Local session engine: browser via CDP, isolated sessions, tabs, temporary profiles.

2. Page understanding: compact text/tree representation (Accessibility Tree) cutting tokens.

3. Natural-language commands: an Adapter turns goals into verifiable actions, with a step limit.

4. Recording and replay: full Trace and deterministic step-by-step replay for diagnosis.

5. Self-healing selectors: semantic properties, fallback chains, logged selection reasons.

6. Structured extraction: JSON matching a Schema, automatic validation, retry on failure.

7. Permissions and policies: allowed domains, blocked dangerous actions, human confirmation, credential masking.

8. Developer interfaces: SDK (Python/TypeScript) + CLI + REST API + log dashboard.

(Out of scope: agent marketplace, multi-cloud expansion, mobile automation.)

4) Pricing and revenue

· Plan · Price · Contents ·

· Community (free) · $0 · Open-source core, unlimited local use, community support. ·

· Cloud Free · $0 · 500 sessions/mo, one project, 7-day logs. ·

· Pro · $29/mo · 10,000 sessions, unlimited replay, 3 projects, 30-day logs. ·

· Team · $99/mo · 5 seats, shared permissions, CI integration, 90-day logs. ·

· Enterprise · Custom · Self-host, SSO, audit logs, DPA, priority support. ·

Revenue logic: free start, developer growth, then paid plans by capacity, collaboration, and compliance; core features stay open.

5) Global launch plan with free channels

• GitHub: open repo, regular releases, examples, good first issue labels.

• Packages: PyPI and npm; trial in one command.

• Communities: Hacker News, Reddit (r/LocalLLaMA, r/webdev, r/automation), official Discord.

• Content: comparisons, "from fragile script to reliable agent" guides, short YouTube videos.

• Integrations: plugins for popular agent libraries (LangChain, LlamaIndex).

• Social proof: Product Hunt, hackathons, live demos.

• SEO: solution pages per use case (QA, extraction, operations), not general marketing.

6) Risks (legal and technical)

Legal:

• Sites used against terms of service or robots.txt — default respect policy; user responsible.

• Data privacy (GDPR/CCPA): short retention, encryption, DPAs, local mode by default.

• No CAPTCHA bypass or anti-protection as a core value.

• Dependency and embedded-browser licenses; trademark rights for the new name.

Technical:

• Site changes and selector failures — self-healing and replay.

• Anti-bot systems and rate limits — respect limits, not evasion.

• Prompt Injection from page content — untrusted input handling and restricted actions.

• Credential protection — secrets vault and least privilege.

• Model cost and latency — page compression and caching repeated steps.

• Resource use and concurrency — session pools and clear limits.

7) Name and tagline

Name: Mirsad
