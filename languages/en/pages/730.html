Mirqab — Complete Project Plan

A lightweight terminal file manager that gives you full visibility and instant speed in one path.

Full execution plan for a new digital project: idea, audience, product, revenue, launch, and risks. Under construction; not yet launched.

Product: native terminal file manager

1) Target audience

• Developers and DevOps engineers working over SSH; they need fast navigation of 10,000+ file projects without leaving the terminal.

• Data engineers and scientists handling large log, CSV, and JSON folders; they need quick previews before copy or move.

• Sysadmins and support engineers managing multiple servers; they need audit logs and rollback for mistakes.

• Researchers and writers organizing libraries of thousands of files; they value fuzzy search and tags over paths.

• Low-spec and Arabic terminal users: 1GB memory, RTL interfaces, and Arabic filenames needing search normalization.

2) Differentiators

• Startup under 40ms and 25MB memory for 100,000 files, versus seconds in graphical managers.

• Instant preview for 20+ formats: text/images via Sixel/Kitty, PDF, ZIP, and Git, max 200ms each.

• Safe operations: internal trash, undo for the last 50 operations, and atomic copy preventing partial files on disconnect.

• Native Arabic: alef, hamza, and taa marbuta normalization, optional RTL, and correct mixed-name display.

• Extensibility: WASM-isolated plugins and a scriptable CLI, e.g. mirqab --pick returning the selected path.

• Remote-first: SSH, SFTP, and S3 browsing; credentials in keychain, not text files; all code from scratch.

3) First-version scope (8 tasks max)

1. Three-column view (parent/current/preview), full keyboard navigation, under 16ms per keypress.

2. Basic text/image preview (Sixel/Kitty), max 5MB each, text fallback if unsupported.

3. Copy, move, regex batch rename with preview, and delete to internal trash.

4. Instant fuzzy search in current/subfolders to 5 levels deep, with Arabic filename normalization.

5. Tabs, bookmarks, and session saving for restoration after restart.

6. Operation log and undo/redo for last 50 operations; optional text audit log.

7. Six built-in plugins: Git, archives, CSV, images, PDF, and open in external editor.

8. Linux/macOS packages via Homebrew, AUR, deb; shareable config; automated performance tests in CI.

4) Pricing and revenue

• Core free forever and open source under MIT, with all local management, preview, and tabs.

• Pro $5/month or $39/year: settings/bookmark sync, 90-day cloud operation log, email support within 24 hours.

• Team $9/user/month: central policies, plugin management, exportable audit log, priority support.

• Lifetime edition $99 per individual; 25% discount for students and schools.

• Plugin marketplace: free publishing, 15% commission on paid plugins, mandatory security review before listing.

• No ads or data selling; extra revenue from enterprise customization at $2,000/deployment plus annual support.

5) Global launch (free channels)

• Launch on GitHub with a public repository and v0.1.0 within 90 days; README animation of 5 operations in 20 seconds.

• Publish in Homebrew, AUR, Flathub, and apt via PPA; target 10,000 installs in 6 months.

• Talks on Hacker News, Lobsters, Reddit (r/commandline, r/rust), with honest answers, not repeated announcements.

• 12 English/Arabic tutorials on real workflows, e.g. “Cleaning 50,000 logs in 3 minutes,” with SEO for terminal file manager.

• Short YouTube/TikTok videos comparing speed with graphical managers; collaborate with 20 small technical creators.

• List in awesome- lists, pitch Linux distribution maintainers, and run a plugin contest with physical prizes.

6) Risks (legal and technical)

• Legal: possible trademark conflict; search 3 jurisdictions (US/EU/JP) before launch; rename if needed.

• Legal: conflicting licenses such as GPL/AGPL may impose conditions; automated cargo-deny checks before each merge.

• Legal: no copying code, assets, or text from prior products; each new file has commit history proving authorship and review.

• Technical: differing terminal image support (Sixel/Kitty/iTerm2); auto-detection and safe text fallback without crashes.

• Technical: data loss on disconnected transfers; atomic copy to temporary file, then rename and integrity check before delete.

• Technical: slowness at millions of files and plugin vulnerabilities; lazy indexing, parallel reads, million-file load tests, and WASM isolation with no default network.

7) Name and tagline

Proposed name: Mirqab (مِرْقَب)

Tagline: A lightweight terminal file manager that gives you full visibility and instant speed in one path.
