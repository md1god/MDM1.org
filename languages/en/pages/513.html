مِحَك — Full Project Plan

مِحَك: Inspect every MCP server, understand its risks, and prove its safety before granting trust.

Implementation plan for a new digital project: idea, audience, product, revenue, go-to-market, risks; under construction, not launched.

1) Audience

Gap: MCP servers spread rapidly and get access to files, commands, and production data before security is verified. The product provides clear inspection and assessment before trust.

• AI agent developers and teams connecting MCP servers to tools.

• Security engineers, DevSecOps, and AppSec.

• Platform/compliance teams needing audit logs and evidence.

• Open-source maintainers and MCP providers.

• SMEs adopting MCP without a dedicated security team.

• Managed service and security consultancies.

2) Differentiators

• Dual inspection: static analysis plus isolated dynamic execution with network blocked by default.

• Explainable assessment: trust score with evidence per finding, not opaque.

• MCP bill of materials: tools, files, networks, secrets reachable by the server.

• Supply-chain risks: tool poisoning, post-approval behavior changes, prompt injection, excessive permissions, secret leaks, shell/production-data access.

• CI/CD gate: policy as code blocks merges above risk threshold.

• Continuous monitoring: rescan on version/config changes with drift alerts.

• Privacy first: local scans by default; secrets never uploaded.

• Transparency: core rules are open; no selling a higher score.

3) First Release (max 8 tasks)

1. Discovery: import common MCP client configs; inventory servers and tools.

2. Static analysis: inspect schemas, permissions, network addresses, exposed secrets, hidden instructions.

3. Isolated dynamic inspection: temp container, canary secrets, no network; monitor file, command, network access.

4. Trust engine: transparent rules + A-F score + severity + remediation guidance.

5. CI/CD: GitHub Action, SARIF/JSON outputs, policy gate blocking risky merges.

6. Monitoring: rescan on version/config changes; compare and show differences.

7. Reporting: signed shareable report, secure-server badge, PDF/JSON export.

8. Free SaaS: accounts, owner-consented public scan log, free-plan limits.

4) Pricing and Revenue

Principle: free to start; pay for scale and enterprise operations, not to raise the security grade.

· Plan · Price · Content ·

· Free · $0 · 3 servers, manual scans, public reports, community rules ·

· Pro · $12/developer/month or $99/year · 25 servers, continuous scans, CI gate, private reports ·

· Business · $29/developer/month · Unlimited servers, SSO/SAML, audit logs, policies, priority support ·

· Enterprise · Custom · Self-hosted/on-prem, SLA, integrations, compliance audit ·

Other sources: self-hosting licenses, manual audits, remediation reviews. Results cannot be bought or affected by plans.

5) Global Go-to-Market with Free Channels

• Open source: CLI and rules engine under Apache-2.0 to build trust and adoption.

• GitHub: free Action and public scans for open-source repos, Marketplace visibility.

• Content: practical guides, MCP incident analyses, "Top 10 Risks" in Arabic/English.

• Communities: Discord, Reddit, Hacker News, MCP and agent-tool communities.

• Partnerships: MCP server providers, agent frameworks, cloud security communities.

• Launch: Product Hunt, technical demos, lightweight CTF server-security challenges.

• Incentives: free badges for secure servers and a bounty program for faulty rules.

6) Legal and Technical Risks

Legal:

• Scanning requires permission or is limited to passive/public scans, with responsible disclosure and safe harbor.

• Findings are heuristic, not guarantees; disclaimer and evidence required.

• Privacy and GDPR: data minimization, local-first, DPAs, no secret uploads.

• Respect licenses/trademarks; do not misuse another project's name.

Technical:

• False positives/negatives: reference test suite and versioned rules.

• Container escape: gVisor or Firecracker, no network by default, temporary environments.

• MCP protocol changes: adapter layer and version compatibility matrix.

• Model nondeterminism and prompt injection: deterministic checks, canaries, repeated runs.

• Scanner supply-chain security: signed releases, SLSA, reproducible builds.

• Abuse: authentication, rate limits, detection of scan reuse for recon.

• Score manipulation: hidden checks, continuous monitoring, verifiable evidence.
