Khayt — Full Project Plan

Local-first platform for building and running reliable browser agents, reproducing every step with humans at the decision core.

A complete implementation plan for a new digital project: the idea, the audience, the product, the revenue model, the go-to-market plan, and the risks. The project is under construction and has not yet launched.

1) Target Audience

• AI agent developers who need inspectable and re-runnable browser automation, not fragile "scripts".

• Automation engineers and QA who want to turn manual test scenarios into reliable workflows.

• Agencies and small teams building data collection or data entry processes for their clients without high cloud costs.

• Data-sensitive enterprises that want to run automation on their own infrastructure with their own model keys or Ollama.

• Researchers and technical content creators who need a free and reproducible experimentation environment.

2) Differentiators (Why Choose Our Product)

• Genuinely local-first: a local web UI launched with a single command, a lightweight on-device runner or inside Docker, support for Ollama and any OpenAI-compatible provider. No need to send browsing data to an external service.

• Dual editor: visual DAG-based building plus full code control via TypeScript or Python, with type-safe variables and instant validation before execution.

• Replay capsule: records every step with screenshots, DOM snapshots, network logs, and model calls, with automatic PII scrubbing, to reproduce bugs precisely.

• Governance instead of stealth: no fingerprint spoofing or CAPTCHA bypass. Instead: allowlisted domains, rate limits, human approval before sending, purchasing, or deleting, and a full audit trail.

• Portable export: convert any workflow into an MCP server, REST API, webhook, or CLI without locking the product to a single provider.

• Built-in evaluation lab: test cases, assertions, regression comparison, and success rate, turning automation from an ad-hoc experiment into a maintainable engineering asset.

3) Scope of the First Version (Maximum 8 Tasks)

1. Local runner with a single command: install via Docker or npm, run Chromium through Playwright, and connect Ollama or an external API key.

2. Web studio: visual editor + code panel, type-safe variables, validation, and local saving.

3. Editable step recorder: records clicks, typing, and navigation, with a selector generator that prefers the accessibility tree over coordinates.

4. Replay capsule: screenshots, DOM, network metadata, console, and LLM calls, with automatic scrubbing of sensitive fields.

5. Concurrent run queue: concurrency control, timeouts, retries, and token and cost budget limits.

6. Policy engine and secrets vault: domain allowlist, human approval for sensitive actions, rate limits, and an audit log.

7. Export and automation: MCP server, REST/webhook, scheduling, and a CLI to run the same workflow outside the studio.

8. Evaluation lab: test data, assertions, result comparison across versions, and an exportable pass/fail report.

4) Pricing and Revenue Model

• Free / Local: free forever for self-hosting; unlimited workflows, 2 concurrent sessions, 7-day local logs, local models or user keys, community support.

• Pro: $19 per user per month; optional cloud sync, 10 concurrent sessions, 30-day logs, scheduled runs, email support.

• Team: $39 per user per month; shared workspace, RBAC and SSO, audit log export, 50 concurrent sessions, 90-day logs, priority support.

• Enterprise: custom pricing; isolated deployment, SLA, compliance review, private connectors, and training.

Revenue: team subscriptions + optional cloud capacity + deployment and integration services. No margin on model keys, and the free local version remains fully usable.

5) Global Go-to-Market Plan with Free Channels

• GitHub first: release the open-source core under the Apache 2.0 license, with workflow templates, beginner-friendly issues, and documented releases.

• SEO and technical content: pages such as "Run browser automation locally", "Self-hosted alternative for agent automation", and cost and privacy comparisons in English and Arabic.

• YouTube and blogs: tutorials building a full workflow in 10 minutes, debugging sessions using replay, and transparent benchmarks between local and cloud models.

• Communities: Show HN, Product Hunt, Ollama and MCP communities, specialized subreddits per their rules, and an official Discord for support.

• Integrations: open templates for n8n, LangChain, LlamaIndex, and Dify, and publishing the MCP server in MCP guides and top tool lists.

• Partnerships: automation agencies, university clubs, hackatho
