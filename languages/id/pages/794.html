SpecWeave — Rencana Proyek Lengkap

Ubah spesifikasi apa pun menjadi suite uji browser hidup yang gagal sebelum pengguna.

Rencana implementasi lengkap: ide, audiens, produk, model bisnis, penyebaran, risiko. Proyek sedang dibangun, belum diluncurkan.

1) Audiens Sasaran

• Pendiri aplikasi AI (Cursor, Bolt, Lovable, v0) rilis 3-5 versi/minggu tanpa QA, menemukan bug di produksi. Contoh: pendiri SaaS merusak alur bayar setelah refactoring.

• Indie hackers pendapatan < $10k/bulan, 1-3 orang, tanpa anggaran Cypress Cloud/BrowserStack.

• Agensi MVP (5-20 karyawan) menyerahkan 4-8 proyek/bulan dan butuh bukti visual bahwa \"spesifikasi selesai\".

• PM perusahaan early-stage (5-30 karyawan) menulis PRD bahasa alami dan tidak membaca TypeScript.

• Pengelola OSS (10k+ bintang) inginkan cakupan E2E tanpa pemeliharaan manual.

• Tim \"vibe coding\" (2-4 dev) pakai Claude Code/Copilot Workspace dan inginkan gerbang kualitas otomatis di PR.

2) Keunggulan

• Spec-first: tiap test diturunkan dari perilaku dinyatakan dengan pemetaan spec→test, mis. \"reset password\" → 3 langkah.

• Free-to-start nyata: 50 run/bulan gratis tanpa kartu untuk repo publik; pesaing minta $39-99/bulan dari awal.

• Laporan kegagalan mudah dibaca: screenshot + video + \"Langkah 3/7: tombol kirim rusak\" bukan stack trace, tautan (7 hari).

• Komentar PR otomatis: GitHub App posting ✅/❌ + ringkasan + tautan laporan, tanpa setup CI.

• Tanpa lock-in: ekspor test sebagai Playwright .spec.ts (100% milik Anda). Self-host runner (MIT) opsional.

• Mock deterministik: rekam HAR sekali, ulang byte-identical → flakiness < 2% (vs 8-15% typical).

3) Cakupan Versi Pertama (8 tugas)

1. GitHub App + webhook PR (install flow + verifikasi HMAC) — 5 hari

2. Spec parser: markdown/isi PR/teks biasa → rencana test JSON (langkah, selector, assertion) — 7 hari

3. Browser runner: Playwright di container dengan replay HAR — 6 hari

4. Halaman laporan kegagalan: screenshot, video, langkah reproduksi, tautan berbagi — 4 hari

5. Bot komentar PR: ringkasan pass/fail + tautan — 3 hari

6. Kuota tier gratis + billing Stripe (50 run/bulan gratis) — 4 hari

7. Dashboard: proyek + riwayat run + ekspor .spec.ts — 4 hari

8. Keamanan: allowlist domain + pengesahan otorisasi pengguna — 3 hari

Total ~36 hari (MVP 6 minggu, 1 dev + 0,5 desainer).

4) Harga dan Model Pendapatan

• Gratis: 50 run/bulan, 1 proyek, repo publik, retention 7 hari. Target: 1.000 pengguna dalam 90 hari.

• Starter $19/bulan: 500 run, 5 proyek, repo pribadi, retention 30 hari.

• Pro $49/bulan: 2.000 run, proyek tak terbatas, runner prioritas, retention 90 hari.

• Team $149/bulan: 10.000 run, SSO (SAML), audit log, 5 seat. Enterprise: kustom (SOC2, on-prem, SLA 99,9%).

• Overage: $0,05/run setelah kuota (usage-based). Biaya: ~$0,012/run → margin kotor ~76% pada Pro.

• Target MRR: $1.700/bulan bulan ke-6 (50 berbayar × $34); $8.500/bulan bulan ke-12 (300 berbayar).

5) Rencana Penyebaran Global dengan Kanal Gratis

• Peluncuran Product Hunt (Selasa 12:01 PT) + 50 upvote seed; target Top 5 hari itu.

• Show HN: \"SpecWeave: turn a PR description into a browser test suite\" — demo Loom 3 menit.

• Reddit: r/SideProject, r/webdev, r/QualityAssurance (1 post/minggu, value-first).

• Twitter/X: 3 thread/minggu (GIF demo before/after) + engage komunitas Cursor/Bolt/Lovable.

• Discord: server Cursor, Bolt, Lovable, v0 — jawab pertanyaan, sebutan lembut. Dev.to/Hashnode: 2 tutorial/bulan.

• Listing GitHub Marketplace (gratis) + badge \"Works with GitHub\" → discovery organik. SEO + YouTube + cold outreach: 10 post/kuartal, tutorial 5 menit, 200 pendiri/minggu via X DM (reply 3%).

6) Risiko (Legal dan Teknis)

• Legal: menguji situs bukan milik pengguna → pengesahan + allowlist domain + ToS. GDPR: hapus HAR (PII) dalam 30 hari, DPA tersedia. Lisensi MIT runner.

• Legal: \"AI-generated tests may miss\" → disclaimer + gerbang review manusia sebelum merge (blok auto-merge opt-in).

• Teknis: test flaky karena konten dinamis → replay HAR + retry 2× + flag karantina (nonaktifkan otomatis flaky > 3 berturut-turut).

• Teknis: biaya LLM/container → cache rencana test berdasarkan hash spec; gunakan ulang antar PR; batas run 5 menit.

• Teknis: halusinasi selector → rekomendasikan data-testid + fallback text/role; confidence < 0,7 → review manusia.

• Teknis: sandbox escape + batas rate GitHub API → container gVisor, tanpa outbound kecuali allowlist, ephemeral; GitHub App (5000 req/jam) + antrian + backoff.
