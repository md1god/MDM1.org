Fennec — Vollständiger Projektplan

Fennec: APIs testen, dokumentieren und teilen – ohne Cloud, blitzschnell.

Vollständiger Umsetzungsplan für ein neues digitales Projekt: Idee, Zielgruppe, Produkt, Geschäftsmodell, Go-to-Market und Risiken. Das Projekt befindet sich in Entwicklung und wurde noch nicht veröffentlicht.

1) Zielgruppe

• Unabhängige Entwickler und kleine Teams (2–10 Personen), die REST/GraphQL/gRPC APIs bauen, 70% nutzen Git täglich und benötigen ein Tool, das sie nicht zu einem Cloud-Konto oder Abo zwingt.

• QA-/Automatisierungsingenieure in Startups (50–500 Mitarbeitende), die nach Preisänderungen bei bestehenden Tools nach einer Alternative suchen; durchschnittlich 4 Tester pro Team, benötigen einen Batch-Runner für CI.

• Studierende und Dozenten an Universitäten (≈2M CS-Studierende weltweit), die ein Offline-Tool für Labore ohne Internet benötigen.

• OSS-Maintainer, die Collections als Code im Repository speichern und über PRs reviewbar machen wollen.

• DevOps/SRE für Smoke-Tests in Pipelines, die einen headless CLI-Runner mit Exit-Codes und JUnit-Report benötigen.

2) Alleinstellungsmerkmale (warum unser Produkt wählen)

• Offline-first: funktioniert vollständig ohne Konto; Daten liegen in einem lokalen Ordner, kein erzwungener Sync.

• Dateibasierte Collections: jede Anfrage = .http/.yaml-Datei, diff-freundlich, git-nativ; kein proprietäres Binärformat.

• Einzelnes Binary <80MB, Start <2s (gegenüber ~8s bei bestehenden Tools), Speicher <200MB.

• Integrierter Mock-Server mit Injektion von Latenz/Fehlern für Contract Testing.

• Optionales AI (Bring your own key) generiert Tests aus OpenAPI-Specs; keine Datenübertragung ohne Zustimmung.

• Plugin SDK (JS) für eigene Auth-Flows + kostenloser Marketplace.

3) Umfang der ersten Version (maximal 8 Aufgaben)

1. HTTP-Client-Engine (Methods, Headers, Body-Typen, SSL, Proxy) + Response-Viewer.

2. Workspace-/Collection-Modell als Dateien gespeichert + Umgebungsvariablen mit Maskierung von Secrets.

3. Pre-/Post-Scripting in JS-Sandbox (QuickJS) + Assertions (expect).

4. Headless CLI-Runner für CI (Exit-Codes, JUnit-Report).

5. Import aus OpenAPI 3.x und Postman Collection v2.1.

6. Mock-Server-Modus, der Collection-Beispiele bereitstellt.

7. Git-aware UI (Status-Badges, Diff-Ansicht) + Konfliktlösung.

8. Plattformübergreifende Paketierung (Windows/macOS/Linux) + signiertes Auto-Update.

4) Preise und Erlösmodell

• Für immer kostenlos: unbegrenzte Collections, lokale Nutzung, CLI, Mock-Server, Imports.

• Pro $8/Nutzer/Monat: optionaler verwalteter Sync, gemeinsame Umgebungen, rollenbasierter Zugriff.

• Enterprise $29/Nutzer/Monat (jährlich): SSO/SAML, Compliance-Export, dedizierter Support.

• Ziele: 100k kostenlose Nutzer in Jahr 1, 3% Konversion → 3000 zahlende → $288k ARR, plus Sponsorships.

5) Globaler Go-to-Market über kostenlose Kanäle

• GitHub-Releases + Homebrew/winget/scoop/apt; SEO-optimierte Landing-Page.

• Inhalte: Tutorials auf Dev.to/Hashnode/YouTube Shorts; Fallstudien.

• Community: Discord, Reddit (r/programming, r/webdev), Hacker News Show HN.

• Integrationen: VS Code Extension, GitHub Actions Marketplace.

• Lokalisierung: i18n für 8 Sprachen; Community-Übersetzung der Docs.

• Universitätsprogramm: Pro kostenlos für Studierende.

6) Risiken (rechtlich und technisch)

• Rechtlich: Trademark-Suche vor der Benennung; kein Kopieren von Code aus Quellen; Lizenzkonformität (Apache/MIT) für Bibliotheken; Bedingungen für AI-Features.

• Technisch: Sicherheit der QuickJS-Sandbox; Umgang mit großen Antworten (Streaming); OS-Keychain für Secrets; Signatur des Auto-Updates; Performance bei 10k+ Requests.

• Markt: Lock-in durch bestehende Tools; Migrationswerkzeuge nötig; Supportaufwand.

• Compliance: GDPR für optionalen Cloud-Sync; Data Residency.

7) Vorgeschlagener Name und Marketing-Slogan

Der vorgeschlagene Name: Fennec

Der Marketing-Slogan: Fennec: APIs ohne Cloud testen, dokumentieren und teilen – blitzschnell.
