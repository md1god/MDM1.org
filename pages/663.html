نمق — خطة مشروع كاملة

اجعل وكلاء البرمجة يبنون واجهات تُشبه البشر، لا القوالب.

خطة أصلية مبنية على احتياج حقيقي وتُراجع قبل التنفيذ.

خطة تنفيذ كاملة لمشروع رقمي جديد: الفكرة والجمهور والمنتج والنموذج الربحي وخطة الانتشار والمخاطر. المشروع قيد البناء ولم يُطلق بعد.

1) الجمهور المستهدف

• مطوّرو الواجهات الأفراد الذين يستخدمون Claude Code أو Cursor أو Codex لتوليد صفحات هبوط سريعة، ويحتاجون ضابط جودة تصميم تلقائي.

• الفرق الصغيرة والستارتبات التي تبني هوية بصرية مميزة ولا تملك فريق تصميم كاملًا.

• وكالات التصميم والتطوير التي تسلّم مواقع لعملاء وتريد ضمان عدم ظهور مخرجات "مولّدة بالذكاء الاصطناعي".

• مهندسو الجودة وDevOps الذين يريدون فحص التصميم داخل CI قبل النشر.

• معلّمو ومحتِجو المحتوى التقني المهتمون بجودة واجهات الويب.

2) نقاط التميز (لماذا نختار منتجنا)

• تقييم حتمي قابل للتفسير: كل مخالفة مرتبطة بقاعدة واضحة ودليل مرئي، لا رأي ذاتي.

• مرتبط بالهوية لا بالذوق العام: "عقد تصميم" مخصص لكل علامة تجارية (ألوان، خطوط، مسافات، نبرة بصرية).

• يعمل مع أي وكيل برمجة: حزمة مهارة + CLI مستقل، دون الارتباط بمزوّد واحد.

• يفحص النتيجة المرئية فعلًا: يحلل DOM وCSS ولقطات الشاشة، لا يكتفي بفحص الكود المصدري.

• يعطي إصلاحًا لا نقدًا فقط: اقتراحات قابلة للتطبيق مع أمثلة كود بديلة.

• مجاني من البداية ومفتوح المصدر: يقلل حاجز التبني ويبني ثقة مجتمعية سريعة.

• خالٍ من "بصمة المولّد": قواعد مصممة من الصفر، بهوية منتج ولغة تصميم مستقلة.

3) نطاق النسخة الأولى (8 مهام كحد أقصى)

1. بناء CLI مفتوح المصدر باسم المنتج يعمل عبر npx، مع حزمة مهارة قابلة للتثبيت في Claude Code وCursor وCodex.

2. محرك قواعد حتمي بصيغة YAML/JSON يضم 60 قاعدة في 6 فئات: التخطيط، الطباعة، اللون، المسافات، المكوّنات، والحركة.

3. كاشف الأنماط الشائعة المكررة: التدرجات البنفسجية الافتراضية، الزوايا المفرطة، الظلال المنتفخة، الأيقونات المستهلكة، والنصوص العامة.

4. محلل واجهة عبر Playwright يقيس التباين، التسلسل الهرمي البصري، الشبكة، الخطوط، والمسافات الفعلية.

5. تقرير نتيجة من 0 إلى 100 مع أدلة مرئية (لقطة + إحداثيات العنصر) وإصلاحات مقترحة قابلة للنسخ.

6. تكامل CI/GitHub Action يفشل البناء عند تجاوز حد جودة محدد، مع تقرير مختصر في الـPR.

7. عقد تصميم قابل للتخصيص لكل مشروع: Design Tokens، استثناءات مسموحة، وملف إعداد واحد.

8. وضع المقارنة قبل/بعد ومعاينة محلية في المتصفح لإظهار أثر الإصلاحات.

4) التسعير ونموذج الربح

• المجاني (Free forever): CLI + المهارة + القواعد الستون + الاستخدام المحلي غير المحدود. مفتوح المصدر بترخيص Apache 2.0.

• Pro — 12 دولارًا شهريًا: تقارير سحابية محفوظة، مقارنات تاريخية، حزم قواعد خاصة، وفحص مشاريع متعددة.

• Team — 29 دولارًا لكل مقعد شهريًا: عقود تصميم مشتركة، سجل CI، صلاحيات، وتكامل مع Slack.

• Enterprise — تسعير مخصص: تشغيل داخلي (on-prem)، SSO، تدقيق، ودعم أولوية.

• مصادر إيراد إضافية: سوق لحزم قواعد تصميم مدفوعة، دقائق CI إضافية، واستشارات تدقيق تصميم.

5) خطة الانتشار العالمية بقنوات مجانية

• GitHub + npm: مستودع مفتوح المصدر، إصدارات منتظمة، وREADME يوضح التحول قبل/بعد.

• أسواق مهارات الوكلاء: نشر المهارة في دلائل ومجتمعات Claude Code وCursor وCodex.

• Product Hunt وHacker News: إطلاق مبني على مقارنة مرئية صادمة بين صفحة "AI slop" وصفحة مصقولة.

• محتوى قصير على YouTube وX وTikTok: فيديوهات 30 ثانية "قبل/بعد" مع النتيجة.

• مقالات SEO تقنية: "كيف تمنع واجهات الذكاء الاصطناعي من الظهور بشكل عام" وأدلة عملية.

• Discord وReddit وdev.to: مجتمعات المطورين والتصميم، مع نسخ مجانية للفرق مفتوحة المصدر.

• شراكات مع قوالب ومكتبات UI: قاعدة قواعد جاهزة لكل إطار عمل، وشارة "تم فحصه".

6) المخاطر (قانونية وتقنية)

قانونية:

• خطر تشابه الاسم أو العلامة التجارية: فحص العلامة قبل الإطلاق وحجز النطاق والحسابات.

• خطر نسخ قواعد أو نصوص من منتجات قائمة: بناء تصنيف القواعد وصياغتها من الصفر وتوثيق المصادر.

• تراخيص المكتبات والخطوط والصور: مراجعة الترخيص والاكتفاء بمكوّنات مسموحة تجاريًا.

• خصوصية لقطات الشاشة: عدم إرسالها للسحابة افتراضيًا، وطلب موافقة صريحة.

• شروط استخدام وكلاء البرمجة: الالتزام بسياسات التكامل وعدم انتحال صفة رسمية.

تقنية:

• النتائج الإيجابية الكاذبة تُضعف الثقة: معايرة القواعد وإتاحة الاستثناءات والتفسير.

• اختلاف العرض بين المتصفحات والخطوط: تثبيت بيئة الفحص وتوثيق حدود الدقة.

• تطور أنماط "AI slop": تحديث القواعد دوريًا عبر مجتمع مفتوح.

• الأداء على المشاريع الكبيرة: فحص انتقائي وتخزين مؤقت.

• تجاوز الفحص بسهولة: دمج الفحص البصري مع قواعد بنيوية، وليس الاعتماد على الكود وحده.

• الاعتماد على وكلاء خارجيين: الحفاظ على CLI مستقل يعمل دون أي وكيل.
