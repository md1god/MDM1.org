Yusr Calendar — خطة مشروع كاملة

تقويم خفيف بلا تعقيد، يعمل مع أي إطار ويحوّل المواعيد إلى تجربة سلسة.

خطة أصلية مبنية على احتياج حقيقي وتُراجع قبل التنفيذ.

خطة تنفيذ كاملة لمشروع رقمي جديد: الفكرة والجمهور والمنتج والنموذج الربحي وخطة الانتشار والمخاطر. المشروع قيد البناء ولم يُطلق بعد.

خطة منتج أصلي: مكتبة تقويم زمني للمطورين

1) الجمهور المستهدف

• مطوّرو الويب الذين يبنون لوحات حجز أو جدولة أو إدارة مهام (SaaS، عيادات، صالونات، تعليم، لوجستيات).

• فرق المنتجات الناشئة التي تحتاج تقويمًا قابلاً للتخصيص دون بناء منطق الوقت من الصفر.

• مطوّرو الإضافات الذين يريدون «نواة» (Core) خفيفة يبنون فوقها واجهاتهم الخاصة.

2) نقاط التميز (لماذا نختار منتجنا)

• نواة مجرّدة (Headless): منطق الوقت والمصادر والمناطق الزمنية منفصل تمامًا عن العرض، مع محوّلات جاهزة لـ React وVue وSvelte وVanilla.

• مناطق زمنية والتوقيت الصيفي (DST) بشكل صحيح من البداية، مع دعم تكرار الأحداث (RRULE).

• أداء عالٍ: عرض افتراضي (Virtualization) يتحمّل آلاف الأحداث بسلاسة.

• السحب والإفلات بإشارات المؤشر واللمس (Pointer/Touch) مع دعم لوحة المفاتيح لإمكانية الوصول (a11y).

• تنسيق عبر متغيرات CSS دون إجبار على مكتبة تصميم معيّنة، ودعم العرض من جهة الخادم (SSR).

• مجاني للبدء ومفتوح المصدر للنواة، بلا قيود على الاستخدام التجاري للنسخة الأساسية.

3) نطاق النسخة الأولى (8 مهام كحد أقصى)

1. نواة منطق الوقت: الأحداث، الفترات، المناطق الزمنية، التكرار الأساسي.

2. تجريد (Headless) API بحالة قابلة للاشتراك (Store) مستقل عن أي إطار.

3. عرض شهري/أسبوعي/يومي مع Virtualization.

4. السحب والإفلات وتغيير الحجم بإشارات المؤشر واللمس.

5. دعم لوحة المفاتيح والتنقل وإمكانية الوصول (ARIA).

6. محوّل React أول + توثيق Vanilla.

7. نظام تنسيق بمتغيرات CSS + وضع داكن/فاتح.

8. توثيق + أمثلة + نشر على npm وموقع توثيق ثابت.

4) التسعير ونموذج الربح

• المجاني (Free): النواة والمحوّلات الأساسية برخصة مفتوحة — بلا حد زمني.

• الاحترافي (Pro): مكوّنات جاهزة متقدمة (واجهات حجز جاهزة، تصدير، تقارير) — اشتراك شهري لكل مطوّر أو ترخيص دائم.

• السحابي (Cloud): مزامنة وحجز جماعي وروابط مواعيد — تسعير حسب الاستخدام/المستخدم النشط.

• الدعم المؤسسي: استشارات وتكييف خاص.

5) خطة الانتشار العالمية بقنوات مجانية

• نشر الحزمة على npm مع README واضح وروابط تجريب مباشرة.

• مستودع مفتوح المصدر + Issues/Discussions لجذب المساهمين.

• محتوى تعليمي: مقالات و«recipes» لحالات شائعة + فيديوهات قصيرة.

• الظهور في مجتمعات المطورين (Reddit، Hacker News، Dev.to، محادثات الأطر).

• قوالب جاهزة على منصات النشر (Vercel/Netlify) للاستخدام الفوري.

• تكاملات مع أدوات شائعة لجذب الزيارات العضوية.

6) المخاطر (قانونية وتقنية)

• قانونية: كتابة كل الكود من الصفر (Clean-room) وعدم نقل أي شيفرة أو أصول أو تسميات؛ التحقق من العلامات التجارية وعدم انتحال هوية أي منتج قائم.

• قانونية: بعض براءات الاختراع حول واجهات السحب والإفلات — الاعتماد على واجهات المتصفح القياسية وتجنّب آليات محفوظة.

• تقنية: تعقيد المناطق الزمنية والتوقيت الصيفي، والتفاوت بين المتصفحات، وأداء الجوال، وإمكانية الوصول.

• تقنية: منافسة مكتبات راسخة — الحل عبر التميّز في التجريد والأداء والتوثيق.
