Nabda — Rencana Proyek Lengkap

Kebugaran dan gizimu di rumahmu, dengan datamu dan kebebasan penuh.

Rencana implementasi lengkap untuk proyek digital baru: ide, audiens, produk, model pendapatan, rencana penyebaran, dan risiko. Proyek sedang dibangun dan belum diluncurkan.

Rencana produk: platform terbuka untuk melacak kebugaran, gizi, dan berat badan (self-hosting terlebih dahulu)

1) Target audiens

• Individu yang peduli privasi dan menolak data kesehatan mereka terhubung ke server komersial tertutup.

• Komunitas self-hosting dan perangkat lunak bebas (homelab, r/selfhosted).

• Pelatih kebugaran dan ahli gizi yang membutuhkan sistem yang dapat dikustomisasi untuk klien mereka tanpa biaya mahal.

• Tim dan klinik kecil yang menginginkan data di infrastruktur mereka sendiri dengan kepatuhan hukum.

2) Keunggulan (mengapa memilih produk kami)

• Data milik pengguna: ekspor penuh dalam format terbuka (JSON/CSV) dan impor yang mulus, tanpa penguncian data.

• Berfungsi tanpa internet: aplikasi web progresif (PWA) yang berfungsi offline dan menyinkronkan nanti.

• Arsitektur ringan: satu kontainer Docker + PostgreSQL, dijalankan di komputer rumah atau VPS kecil.

• API pertama: antarmuka REST terdokumentasi dan sandbox, dengan dukungan integrasi jam pintar melalui protokol terbuka.

• Kustomisasi tanpa kode: editor jadwal latihan dengan seret dan lepas, serta dukungan RTL dan terjemahan penuh sejak hari pertama.

• Benar-benar gratis untuk memulai: inti bebas tanpa batas fitur, dan keuntungan dari layanan bukan dari memblokir hal-hal dasar.

3) Cakupan versi pertama (maksimal 8 tugas)

1. Mencatat latihan harian dan membangun jadwal latihan yang fleksibel (set/repetisi/beban).

2. Perpustakaan latihan yang dapat diperluas dengan tag otot dan peralatan.

3. Pelacakan berat badan dan ukuran tubuh serta grafik waktu.

4. Pelacakan gizi: kalori + makro + basis makanan umum yang dapat diedit.

5. Aplikasi web + PWA untuk seluler dengan fungsi offline dan sinkronisasi.

6. REST API terdokumentasi + Webhooks + sistem plugin (plugins).

7. Banyak pengguna, peran dan izin, serta menghubungkan pelatih dengan kliennya.

8. Ekspor/impor penuh data + cadangan terenkripsi dan perintah sekali jalan untuk penyiapan.

Tumpukan teknologi yang diusulkan: Go atau Python untuk backend, PostgreSQL, antarmuka Next.js/React, kontainer Docker, dokumentasi OpenAPI.

4) Harga dan model pendapatan

• Versi gratis (self-hosting): semua fitur inti gratis selamanya, lisensi bebas yang melarang penutupan komersial.

• Cloud terkelola (Freemium): lapisan gratis dengan batas penyimpanan sederhana, lalu paket bulanan (misalnya 5$ / 10$ / 20$) untuk sinkronisasi otomatis, pencadangan, dan dukungan.

• Paket Tim/Klinik: langganan berdasarkan jumlah pengguna + login tunggal (SSO) + laporan.

• Dukungan dan konsultasi + Marketplace untuk plugin berbayar (pengembang menyimpan persentase).

• Prinsip: gratis untuk memulai, dan membayar untuk kenyamanan dan pemeliharaan bukan untuk fitur dasar.

5) Rencana penyebaran global melalui saluran gratis

• Publikasi di GitHub dengan README yang kuat, gambar ilustratif, dan demo langsung.

• Pencantuman di daftar awesome-selfhosted dan Awesome Privacy dan AlternativeTo.

• Peluncuran serentak di Hacker News dan Product Hunt dan Reddit (r/selfhosted, r/QuantifiedSelf, r/opensource).

• Konten teknis: artikel tentang "kepemilikan data kesehatan" di Dev.to dan Hashnode dan kanal YouTube kecil.

• Komunitas terbuka: Lemmy dan Mastodon dan Discord, dengan program kontributor dan imbalan simbolis.

• Lokalisasi dan terjemahan komunitas melalui Weblate untuk membuka pasar baru tanpa anggaran pemasaran.

6) Risiko (hukum dan teknis)

Hukum:

• Privasi data kesehatan: kepatuhan pada GDPR dan sejenisnya, enkripsi saat transit dan diam, serta kebijakan privasi yang jelas.

• Penafian medis yang eksplisit (produk bukan alat diagnosis atau pengobatan).

• Kesesuaian lisensi bebas dan larangan penutupan komersial kembali, serta pemeriksaan paten pada nama dan logo.

• Tidak memberikan klaim medis pemasaran yang tidak terbukti.

Teknis:

• Konflik sinkronisasi antara beberapa perangkat offline dan solusinya melalui CRDT atau stempel waktu.

• Keamanan self-hosting (konfigurasi lemah dari pengguna) → template aman secara default dan pembaruan otomatis.

• Skalabilitas dengan kepadatan data tinggi, dan pengujian migrasi data.

• Kualitas basis makanan dan keragamannya serta sumber dan lisensinya.

7) Nama yang diusulkan dan slogan pemasaran

Nama yang diusulkan: Nabda (نَبضة)

Slogan pemasaran: Kebugaran dan gizimu di rumahmu, dengan datamu dan kebebasan penuh.
