Masar CI — полный план проекта

От кода до релиза в один шаг. Лёгкий CI/CD для вашего собственного сервера.

Полный план реализации нового цифрового проекта: идея, аудитория, продукт, модель монетизации, план запуска и риски. Проект в разработке и ещё не запущен.

1) Целевая аудитория

• Небольшие и средние команды (2–30 разработчиков), которым нужна лёгкая система CI/CD, работающая на их собственном сервере без лишней сложности.

• Компании, ищущие экономичную альтернативу дорогим CI/CD-платформам, с полным контролем над своими данными и оборудованием.

• Разработчики open source проектов и сообщества самохостинга (маленькие VPS, ARM-устройства, домашние сервера).

• DevOps-инженеры в стартапах, которые хотят запускать пайплайны локально перед переносом их в облако.

2) Ключевые преимущества (почему выбирают наш продукт)

• Локальный запуск в первую очередь: одна команда запускает пайплайн на самом устройстве разработчика с тем же результатом, что и на сервере — меньше расхождений в духе «у меня работает».

• Единственный конфигурационный файл с хорошей документацией: каждый шаг читается из простого YAML-файла с мгновенной проверкой (Validation) и подсказками по исправлению прямо в редакторе.

• Крайне лёгкий: всего два компонента (сервер + исполнитель), по умолчанию база данных SQLite, потребление памяти в холостом режиме менее 100 МБ.

• Надёжная изоляция выполнения: каждая задача работает в отдельном контейнере с ограничениями по ресурсам и изолированной сетью, с автоматической очисткой.

• Встроенный кэш: повторное использование результатов сборки и зависимостей между запусками, без внешних плагинов.

• Полноценные арабский и английский интерфейсы с первого дня, а также визуальный редактор для просмотра результатов шагов в реальном времени.

• Масштабируемость через единые плагины (один стабильный API для всех официальных и сторонних расширений).

3) Объём первой версии (максимум 8 задач)

1. Сервер (управление проектами, права доступа, журналы задач) на языке Go с хранением в SQLite.

2. Исполнитель (Runner) на контейнерах Docker/Podman с ограничением ресурсов и изолированной сетью.

3. Парсер YAML-файлов пайплайнов с мгновенной валидацией и понятными сообщениями об ошибках.

4. Интеграция с GitHub/GitLab/Forgejo: чтение пушей, создание коммитов, привязка pull request'ов к результатам проверок.

5. Безопасность: шифрование секретов, права на уровне проекта, изоляция задач участников.

6. Веб-интерфейс (React): состояние каждого шага, живые логи, скачивание артефактов (Artifacts).

7. Встроенный кэш + возможность перезапуска с указанного шага.

8. CLI-инструмент для локального запуска пайплайна и проверки файла перед пушем.

5) План глобального запуска через бесплатные каналы

1. GitHub/Social: открытый репозиторий + лендинг + короткие скринкасты в X и LinkedIn.

2. Сообщества разработчиков: публикации на Reddit (r/devops, r/selfhosted), Hacker News (Show HN), форумы по самохостингу.

3. Арабский и английский контент: статьи на Dev.to, Hashnode и Midudev, обучающие видео на YouTube.

4. Документация как инструмент маркетинга: гайды «начни за 5 минут» и готовые шаблоны, оптимизированные для поисковых систем.

5. Технический блог: еженедельные разборы реальных проблем CI/CD и сравнения производительности с цифрами.

6. Сообщество Discord/Matrix для пользователей + программа амбассадоров (Ambassadors) для университетов и групп разработчиков.

7. Каталог плагинов и шаблонов позволяет сообществу публиковать свои решения и привлекает постоянный поисковый трафик.

8. Product Hunt и OSS-конференции: согласованный запуск с временными акциями на облачные тарифы.

6) Риски (юридические и технические)

Юридические:

• Совпадение названий брендов: проверка товарных знаков перед запуском на целевых рынках.

• Лицензия: выбор прозрачной лицензии (например, Apache-2.0) и проверка совместимости зависимостей Go и API-интерфейсов с этой лицензией.
