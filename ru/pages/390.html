Mawja — полный план проекта

Найдите бесплатное место до того, как оно исчезнет.

Полный план реализации нового цифрового проекта: идея, аудитория, продукт, монетизация, план запуска и риски. Проект в разработке, ещё не запущен.

1) Целевая аудитория

• Индивидуальные путешественники, бронирующие рейсы за мили и баллы (Miles & Points) и ищущие бесплатные наградные места (Award Seats) без обхода десятков сайтов авиакомпаний.

• Участники нескольких программ лояльности (например, Flying Blue, LifeMiles, Miles+Bonus), использующих их одновременно.

• Семьи, которым нужно 4 и более места на одном рейсе — вручную их найти практически невозможно.

• Консультанты по планированию поездок и профессиональные Points Brokers, которым нужна гибкость дат и направлений.

• Частые путешественники (Digital Nomads) с гибкими датами и направлениями.

2) Преимущества (почему выбирают наш продукт)

• Параллельный поиск в десятках программ лояльности за один раз вместо перехода с сайта на сайт.

• Умные фильтры: число пассажиров, класс рейса, ближайшие аэропорты (Nearby Airports) и гибкое окно дат.

• Мгновенные уведомления по Email + Telegram + Web Push при появлении подходящего места.

• Панель «гибкости дат» визуально показывает самый дешёвый день месяца.

• Интеграция с популярными системами бронирования через готовые поисковые ссылки, без бронирования за пользователя (без посредничества).

• Полноценный арабский интерфейс + поддержка григорианского и исламского календарей, чего обычно нет в этой категории.

• Бесплатный старт: минимум один поиск и одно уведомление без банковской карты.

3) Объём первой версии (максимум 8 задач)

1. Фирменный стиль: логотип, цвета, система Typography, интерфейс на арабском/английском (RTL/LTR).

2. Базовая модель данных: направления, даты, программы лояльности, классы и число доступных мест.

3. Поисковый движок на Frontend с базовыми фильтрами и мгновенными результатами.

4. Слой сбора/обновления данных (Backend Jobs) из заявленных источников или API-провайдеров, с кешем для защиты от превышения лимитов.

5. Система уведомлений: создание «поискового сохранения» + отправка писем и push-уведомлений в браузере.

6. Личный кабинет: сохранённые поиски, активные уведомления и история результатов.

7. Лендинг + вход по Magic Link + бесплатный/платный тарифы.

8. Базовая Analytics и инструмент оценки качества результатов (свежесть и точность).

4) Тарифы и модель доходов

• Бесплатно: безлимитный поиск, одно сохранённое условие, одно уведомление, ежедневное обновление с задержкой.

• Plus — 9$/мес: 20 сохранённых поисков, мгновенные уведомления, гибкость дат, мультиканальные уведомления.

• Pro — 29$/мес: безлимит + API + продвинутые Telegram-уведомления + ближайшие аэропорты + приоритетная поддержка.

• B2B: пакет для консультантов по поездкам (59–149$/мес) на несколько клиентов.

• Дополнительный доход: реферальные ссылки на кошельки и приветственные программы, явно указанные, без продажи данных пользователей.

5) План глобального запуска через бесплатные каналы

• SEO-контент на арабском/английском: «как забронировать бесплатное место за points» + таблицы популярных направлений.

• Статьи-сравнения программ лояльности и пошаговые руководства для каждой.

• Reddit и форумы FlyerTalk/MileageRun + группы в Facebook и Telegram о баллах.

• Короткие видео (TikTok/Reels/YouTube Shorts) с живыми результатами поиска «до/после».

• Бесплатная еженедельная рассылка: «5 лучших бесплатных мест на этой неделе».

• Партнёрства с арабскими и мировыми travel-блогерами через бесплатную реферальную программу.

• Product Hunt + группы в Slack/Discord для ранних пользователей.

6) Риски (юридические и технические)

• Юридические: соблюдение условий использования сайтов авиакомпаний и программ лояльности; отказ от прямого использования их логотипов без лицензии; политика конфиденциальности (GDPR/CCPA) и явное согласие на хранение уведомлений; дисклеймер, что наличие мест меняется мгновенно.

• Технические: изменение интерфейсов (Scraping) или ограничение лимитов (Rate Limits) ⇒ ориентироваться в первую очередь на официальные/сторонние API + кеш + уведомление при снижении качества данных.

• Точность: устаревшие данные разрушают доверие ⇒ измерять время обновления и долю валидных результатов как ключевой показатель.

• Операционные: стоимость обращений к провайдерам ⇒ постепенный апгрейд тарифа по мере использования.

• Конкуренция: вход крупного игрока ⇒ отстройка через арабский рынок, гибкость и цену.
