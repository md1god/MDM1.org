Zakira — полный план проекта

Постоянная память для AI-агентов, local-first и под вашим полным контролем.

Полный план реализации нового цифрового проекта: идея, аудитория, продукт, модель монетизации, план продвижения и риски. Проект в стадии разработки и ещё не запущен.

Продуктовый план: постоянный слой памяти и контекста для агентов искусственного интеллекта

1) Целевая аудитория

• Отдельные разработчики: те, кто создаёт агентов для программирования или общения и теряет контекст между сессиями.

• Малые и средние инженерные команды: нужна общая память между участниками команды без привязки к одному поставщику.

• Организации с требованиями к приватности: хотят запускать решение локально (on-prem) из-за чувствительных данных.

• Создатели инструментов AI: те, кто ищет готовый слой через унифицированный протокол (например, MCP) вместо построения решения внутри.

2) Ключевые преимущества (почему выбирают наш продукт)

• Local-first: данные по умолчанию хранятся у пользователя, с опциональной шифрованной облачной синхронизацией.

• Нейтральность к поставщику: работает с любой моделью или фреймворком через унифицированный интерфейс, без вендор-лока.

• Прозрачная и редактируемая память: пользователь видит, что сохранено, и может это изменить или удалить, в отличие от «чёрного ящика».

• Полный контроль над забыванием: срок жизни (TTL), классификация чувствительности и явные команды «игнорировать/удалить».

• Более точный гибридный поиск: объединение семантического поиска с графом знаний (graph) и учётом новизны и важности для снижения расхода tokens.

• Аудируемость: журнал, показывающий, какая память была включена в какой контекст и почему.

3) Объём первой версии (не более 8 задач)

1. Пакет SDK/CLI + локальное хранилище (SQLite + лёгкий векторный индекс).

2. Интерфейс захвата событий сессии (вызовы инструментов, файлы, решения).

3. Конвейер сжатия и постепенного суммирования памяти.

4. Движок гибридного поиска (семантика + граф знаний + новизна + важность).

5. Сервер, совместимый с протоколом MCP, для лёгкого подключения агентов.

6. Визуальная панель управления для просмотра/редактирования/удаления/установки срока памяти.

7. Экспорт/импорт + шифрование при хранении.

8. Простое развёртывание через Docker + базовая аутентификация.

4) Ценообразование и модель прибыли

• Бесплатный старт: self-hosted с открытым исходным кодом без ограничений, + бесплатный облачный уровень (один проект / определённый лимит tokens).

• Pro: ~12$/месяц — синхронизация, расширенный поиск, резервное копирование.

• Team: ~29$/пользователь/месяц — общие пространства, роли, аудит.

• Enterprise: лицензия с самостоятельным хостингом + поддержка и кастомная интеграция.

• Дополнительная выручка: платная поддержка, готовые интеграции, маркетплейс дополнений памяти.

5) Глобальный план продвижения через бесплатные каналы

• Публикация кода с открытым исходным кодом на GitHub + попадание в каталоги MCP и «awesome lists».

• Запуск на Hacker News, Product Hunt, Reddit (r/LocalLLaMA, r/MachineLearning) и Dev.to.

• Обучающий контент: живая демонстрация «до/после» наличия контекста + документация по реальным сценариям.

• Готовые интеграции с популярными фреймворками (LangChain/LlamaIndex) и написание запускаемых примеров.

• Сообщество Discord + ежемесячные испытания + программа ранних контрибьюторов.

• Многоязычная документация (арабский/английский) для охвата разработчиков по всему миру.

6) Риски (юридические и технические)

Юридические:

• Приватность данных (GDPR/CCPA) и право на забвение — нужно фактическое удаление и явное согласие.

• Открытая лицензия не должна запутанно ограничивать коммерческое использование.

• Соблюдение условий поставщиков моделей при передаче сохранённого контекста.

• Права на сохранённый контент и права пользователя, а также избегание любого копирования существующих продуктов.

Технические:

• Качество поиска и галлюцинация неверных воспоминаний, сбивающая агента.

• Атака инъекции команд через память, захваченную из внешних источников.

• Ограничения окна контекста и рост стоимости embeddings при масштабировании.

• Изменение интерфейсов моделей и поломка интеграций.

• Безопасность локального хранилища и синхронизации и предотвращение утечки данных.
