Атар — полный план проекта

Твоя история перемещений — только твоя.

Полный план реализации нового цифрового проекта: идея, аудитория, продукт, бизнес-модель, план распространения и риски. Проект находится в разработке и ещё не запущен.

План продукта: самохостящийся альтернативный сервис для отслеживания перемещений

1) Целевая аудитория

• Люди, заботящиеся о конфиденциальности, которые хотят вести запись своих ежедневных перемещений без передачи данных рекламным компаниям.

• Опытные пользователи и администраторы серверов (homelab), самостоятельно хостящие свои сервисы.

• Небольшие семьи, желающие по желанию делиться местоположением между своими членами.

• Небольшие полевые команды (курьеры, полевые исследователи), нуждающиеся в частном журнале маршрутов.

2) Ключевые преимущества (почему наш продукт)

• Конфиденциальность прежде всего: все данные остаются на устройстве пользователя или его сервере, с шифрованием при хранении.

• Работает без выделенного сервера: локальный запуск на одном устройстве с возможностью опционального управляемого облачного варианта.

• Широкая совместимость с источниками геолокации: принимает данные из трекинговых приложений, импортируемых из мобильных сетей (GPX/GeoJSON) и унифицированных программных интерфейсов.

• Умный журнал: автоматически преобразует сырые точки в «места» и «поездки» вместо отображения разрозненных маршрутов.

• Полный экспорт без ограничений: пользователь может в любой момент получить свои данные в открытом формате — без удержания данных.

• Нативный интерфейс с поддержкой русского и других языков, без постобработки перевода.

• Низкое потребление ресурсов: работает на маломощных устройствах, в отличие от многих тяжёлых альтернатив.

3) Объём первой версии (не более 8 задач)

1. Импорт точек из GPX/GeoJSON и через простой унифицированный программный интерфейс для загрузки местоположения.

2. Отображение маршрутов на интерактивной карте с временной шкалой.

3. Автоматическая классификация на «места» и «поездки» по времени остановок и движения.

4. Базовая статистика: пройденное расстояние, время, наиболее часто посещаемые места.

5. Ручное именование мест и их сохранение (дом, работа, ...).

6. Возможность поделиться одноразовой ссылкой на конкретную поездку с кодом доступа.

7. Полный экспорт данных и окончательное удаление аккаунта через интерфейс.

8. Самохостинг одной командой через Docker Compose с настройкой шифрования хранилища.

4) Ценообразование и бизнес-модель (сначала бесплатно)

• Бесплатно (навсегда): полный самохостинг со всеми основными функциями, без ограничений по объёму данных.

• Облачный «поддерживаемый» (платная подписка): управляемый трекинг без настройки сервера, с резервным копированием и увеличенным объёмом хранилища.

• Семейный тариф: несколько мест и расширенная возможность обмена ссылками.

• Корпоративный тариф для команд: индивидуальный внутренний запуск, поддержка и аутентификация через SSO.

• Модель строится на оплате за удобство и хостинг, а не за блокировку функций.

5) План глобального распространения через бесплатные каналы

• Публикация кода в качестве проекта с открытым исходным кодом для привлечения контрибьюторов и повышения доверия.

• Появление в списках «альтернатив самохостинга», «awesome self-hosted» и специализированных сообществах Reddit.

• Публикация практических руководств и честных сравнений в блоге и на Hacker News.

• Короткие видеоинструкции по установке за две минуты на YouTube/PeerTube.

• Продвижение в сообществах Mastodon и Telegram, посвящённых конфиденциальности.

• Запуск на Product Hunt с демонстрацией импорта данных пользователя из любого источника.

• Программа амбассадоров для семей и небольших команд с небольшой комиссией.

6) Риски (юридические и технические)

• Юридический: совместное использование местоположения между людьми может быть использовано для слежки — решается через явное согласие, постоянное уведомление и возможность немедленного отключения.

• Юридический: различия в законах о защите данных между странами (GDPR и др.) при расширении облачного сервиса — минимизация сбора данных и выбор региона хостинга.

• Технический: точность определения «мест» зависит от плотности точек — применяются настраиваемые алгоритмы.

• Технический: расход батареи в мобильных приложениях — оптимизация интервалов записи и пакетной передачи.

• Технический: безопасность самохостящихся серверов, открытых в интернет — принудительное использование HTTPS и предупреждения при настройке.

• Коммерческий: сложность получения дохода от аудитории, привыкшей к бесплатным решениям — акцент на управляемые сервисы и подде
